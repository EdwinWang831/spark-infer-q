# Kaifra v0.4.1 四请求 128K prefill 优化

2026-11-03。[事前方案](ENGINE_V05_PLAN.md) · [中文用法](ENGINE_V05_USAGE.md) ·
[English usage](ENGINE_V05_USAGE.en.md) · [脱敏证据](../results/engine/2026-11-03-v05.json)。

同一常驻模型、同一套四槽 Graph，四请求各 131008 输入加 64 输出，ABBA
两组配对的完整引擎 cohort 平均 **476.62 → 387.62 秒**，耗时减少
**18.67%**。两组候选均更快，输出、有效状态、特征及动态轨迹全部一致。

## 配置与内存

A 使用 512 行 prefill、原专家算子和镜像特征窗口。B 使用 1024 行 prefill、
已有 E44 专家 tile 和单缓冲连续特征窗口。两者都保留完整 2040 行草稿
特征、BF16 target K/V、原始索引环及冻结 E17/E29 动态预算。

单缓冲窗口滚动时复制有效后缀，先保护新输入，再移动保留数据，返回连续
借用视图。每请求实际持久存储从 104448000 降到 52224000 bytes，
四请求减少 208896000 bytes，约 0.195 GiB。追加的临时副本合计最多
一个窗口，约 49.8 MiB，复制开销计入执行。

腾出的空间使 1024 行配置通过原准入条件。同期启动预测约为 A 87.90、
B 87.94 GiB，完整配对验证峰值 allocated **87.00 GiB**、reserved
**87.66 GiB**，主机最低采样可用内存 **17.38 GiB**。更大的 prefill
工作区与更小的特征窗口共同决定总量，单列的窗口节省用于说明持久存储。

E44 tile 沿用 Mia/TensorFold 算子与已校验二进制，归属和既有结果见
[E44](E44_MIA_PREFILL_TILE_REPORT.md)。本轮比较的是分块、专家实现、
配套原生 prompt 预算及特征存储的组合，逐项消融属于另外的实验。

## 正确性与复核

GPU 预检覆盖 1024、1025、4097 行输入，核对完整 logits、五层特征及
全部有效状态，另完成 24 组后续 Graph／部分提交。两种窗口按分段追加
核对有效后缀和绝对位置，实际 tensor 字节数符合单份／双份存储。

正式 16 条请求的输出 token、完整有效 K/V／GDN／PLE 状态及末尾 2040 行
特征，均匹配 v0.4 已封存的逐 token 控制。四个同期运行的预测率、验证
宽度与接受轨迹一致。正式计时内 target Graph 捕获数保持 64，草稿新增
捕获为零，head kernel 集合稳定，Graph 与 head 回退为零。

本地 CPU 共 504 项，463 通过，41 项可选环境跳过。窗口测试覆盖回绕、
大块追加、借用视图、百万逻辑行、请求隔离及实际存储字节，准入测试
核对单缓冲按一份计费。模型 PID 和 target/draft 对象贯穿实验，
`load_count=1`。

## 常驻服务与独立客户端

常驻服务已启用 E44、1024 行 prefill 和单缓冲特征。独立标准库客户端
提交原始 messages，包含聊天模板、分词、HTTP 和完整推理，四请求 cohort
为 **395.42 秒**，工作量仍为 524032 输入加 256 输出 tokens。四条文本
与 token usage 都匹配封存控制。原生引擎配对与公开 HTTP 分别计时。

同时观察到四运行加四等待，第九个请求返回 429。短请求取消后的三个
幸存者与各自重放一致，断连恢复通过。最终 19 请求正常完成、2 取消，
失败请求和 worker 失败均为零，运行、等待和在途流全部回到零。
模型继续常驻，部署期间 `load_count=1`。

wheel 在独立环境安装，仓库外 CLI 与新参数通过检查，全部生产 Python
文件与配对／GPU／实际服务快照逐字节一致，上游许可证随包提供。
本轮使用已加载模型，冷启动历史见 [v0.1](ENGINE_V01_REPORT.md)。

## 采集器失败记录

首次采集在数值检查及两种预热通过后、正式样本开始前被预算拒绝。
切换配置后，已释放的工作区留在 allocator 缓存中，原公式又把这些缓存
加作未来暂存需求。采集器改为对已分配四槽计算新请求特征加 1 GiB 暂存，
同时单独检查当前 reserved 和主机余量。88 GiB 分配器限额、8 GiB 主机
余量与 1 GiB 暂存条件继续参与验收。第二版重新完成全部预检、预热和
ABBA，首次拒绝及 traceback 保留，预热耗时单独归档。

普通 CLI 采用镜像／512 行配置，已准备好 E44 扩展的环境可显式启用新配置。
本轮证据覆盖四条合成提示与每条 64 输出。长 GPU 合批、长期压力、
长答案质量与 1M 容量继续单独验证。
