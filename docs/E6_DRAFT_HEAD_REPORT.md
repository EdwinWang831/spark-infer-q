# E6：DFlash2 草稿头成本与压缩

2026-10-21。方法见[冻结设计](E6_DRAFT_HEAD_PLAN.md)，其他使用者的接口、配置和硬件边界见[中英使用说明](DRAFT_HEAD_USAGE.md)。本轮使用 E3/E4 单请求 speculative 循环，与 E5 独立 target-only Scheduler 桥接分开。

## 实测结论

**本轮应优先保留完整词表的 Q4 草稿头。** 在八条新任务上，它的动态 decode 为 **45.54 token/s**，同任务 BF16-full 动态基线为 **41.70 token/s（+9.23%）**；固定七草稿从 40.88 到 44.78（+9.53%）。四次重复按各自全任务耗时求和，动态配对速度比为 1.0850 / 1.1081 / 1.1036 / 1.0902；这是这组任务上的重复稳定性观测，不是总体置信区间。

| 草稿头 | fixed7 token/s | dynamic7 token/s | 动态相对 BF16-full | 单配置新增 payload |
| --- | ---: | ---: | ---: | ---: |
| 完整 BF16（共享） | 40.88 | 41.70 | +0.00% | 0.00 MiB |
| 固定子词表 BF16 | 35.86 | 41.58 | -0.28% | 389.24 MiB |
| 完整 Q4 | 44.78 | 45.54 | +9.23% | 378.91 MiB |
| 固定子词表 Q4 | 37.30 | 43.76 | +4.94% | 122.09 MiB |

这里的 327 个 decode token 为八任务共同的实际输出数（各排除首个 pending token）；每模式四次重复，总计 **256 次正式计时**。所有八任务自然 EOS，无截断；**64 次独立 oracle** 检查 **2,616 行已提交完整 logits** 与有效状态，另有全部 256 次计时的输出/状态核对。五条可客观检查的独立答案（中文 JSON、两个 Python 函数、两个算术）全部通过；散文/LaTeX 没有语义评分。完整输出、逐次耗时、接受计数、宽度与组件成本保留在[公开数据](../results/e6/2026-10-21-draft-head.json)。

完整 Q4 的投影+top-k 中位耗时从 **6.151 降至 2.259 ms**，完整 proposer 从 **13.540 降至 9.657 ms（耗时 −28.68%）**。四个校准上下文的 full top-16 平均重合 **94.64%**，top-1 和最终 selector 提案均为 **27/28 一致（96.43%）**；全 logits 相对 BF16 的平均 L2 差异约 **8.32%**，最大绝对差 1.293。可说这组诊断中提案接近，不能称数值无损或通用 BF16 fidelity。最终生成的一致性由未变的 target 验证保证，并已实测核对。

固定子词表带来清楚的语言覆盖代价：两条英文校准上下文的 BF16-subset 提案为 14/14 一致，两条中文上下文仅 1/14；Q4-subset 同样如此。中文解释任务中，动态 BF16-full / Q4-full / Q4-subset 分别为 **25.40 / 26.95 / 22.84 token/s**。而 Python merge 任务为 **73.30 / 76.70 / 80.42**。因此不能向其他使用者统一推荐这个固定子词表，也不能只比较保留行的 logits L2 就称覆盖无损。

动态预算在完整 Q4 上比 fixed7 再快 **1.72%**；子词表 Q4 上则快 **17.32%**，会选零草稿跳过昂贵的无效 proposer，但其全任务动态结果仍低于完整 Q4。固定策略的接受/观测草稿比为 BF16-full 37.85%、Q4-full 39.51%；两者提案已变化，收益不能全部归为同轨迹 kernel 成本缩减，也不证明量化普遍提高草稿质量。动态策略的接受比例受所选草稿数与跳过决策影响，不能跨策略直接充当 fidelity 分数。

冷 prompt+decode 的前两任务、各两次重复共 **16 次控制**：BF16-full 两任务中位耗时之和 **5752.40 ms**，Q4-full **5486.38 ms（总时延 −4.62%）**。这是次要、小样本 executor 内对照。target 特征/验证仍占 Q4-full 动态 decode 约 **84.18%**，整个草稿约 **14.26%**；下一轮速度瓶颈已进一步偏向主模型路径。

共同驻留的 allocated/reserved 为 **72.51 / 73.88 GiB**；含加载的全程 peak allocated/reserved 为 **73.44 / 74.41 GiB**，没有 OOM。只计算一个全词表 Q4 副本约 **378.91 MiB**；原 BF16 head 仍保留，不能声称整模因此省内存。target head 前后完整 SHA256 相同（`40bddd25d0d94a128ab08280faad39cfc3ee3064252761269115f544722607c9`）。实验 worker 已结束，实验容器已停止，OOMKilled 为 false；容器停止后的退出码不作为模型正确性证据。

后续候选保留完整词表 Q4 与 BF16 对照，不把子词表配置设为全局默认。若使用者要求更高的草稿数值 fidelity，Q8/混合精度需新增后端并单独测量，目前没有对应性能或跨 GPU 证据。本轮没有修改默认服务或导出/发布量化权重文件。

## 对照与归因

四配置只替换草稿投影：共享完整 BF16；固定外部 TensorFold 子词表 BF16；完整 group-32 affine Q4；同子词表 Q4。全词表 248,320 行，子词表 79,591 行，合并 EOS 后数量不变。子词表 SHA256 `88d5b483a849ae9245b78b69f41f11cdfc8b5c024f0786c1c8196263857cc93e`。每种投影均在 selector 前还原全局 token ID。target、embedding、五层草稿 backbone 和 selector 不变。

子词表和 Q4 来源于 TensorFold，原生 MTP 已使用这些方法；它们本身不是本项目的算法创新。本轮研究的是它们与当前 DFlash2 proposer、接受前缀提交、DeepInfer 原生动态预算的实际组合效果。

两条独立中英提示用于成本/接受率校准并冻结；四个真实上下文用于组件成本和草稿 fidelity 诊断。八条新任务包含中英解释、中文 JSON、LaTeX、两个可执行 Python 函数、普通与 thinking 算术。任务生成前即固定，不按快慢或答案成败筛选。每 head 同时运行 fixed7 和原生 dynamic7（零至七草稿），四次重复；head 四阶循环位置平衡，配对预算交替先后，不称八配置完整 Latin square。

计时为同步 host decode 总耗时，包含 drafter、target 特征、verify、commit 和控制；排除 load、prompt、初始 clone、独立 oracle 与计时后状态比较。逐任务耗时中位数求和后除实际 decode token，不平均 TPS。另有前两任务 fixed7 的 16 次冷 prompt+decode executor 内控制；不是网络/API TTFT。全部四头共同驻留。

## 正确性与复用边界

Q4 内核已在 SM121 编译。独立解包后的 FP32 参考验证 12 例（输出列 128/259、行 1/7/8、默认/独立 stream）；最大相对 L2 约 `1.50e-7`，最大绝对差 `7.16e-7`。这是**已存 Q4 权重的算术检查**，不是相对 BF16 的量化无损证明。一次预检查因源代码快照未包含 `draft_vocab.txt` 而失败，尚未加载模型；改为显式 `--draft-vocab` 输入已安装的外部固定词表后通过。

每配置/预算均独立对照同路径 serial oracle，比较已提交完整 logits 与最终有效 GDN/QSA 状态；每次计时另核对完整输出 IDs 和最终有效状态。BF16-full 包装器与原 proposer 的 hidden、top-k 与提案严格回归。target BF16 head 做前后全量 SHA256，确认未被修改。散文/LaTeX不作语义评分；截断代码仅作前缀，不称完整正确程序。

压缩头是新增副本：target BF16 head 仍需保留。共享 BF16 草稿新增权重为零，压缩可能提高速度却增加整机常驻内存。每配置 payload 与共同驻留/全程峰值分别报告，不能把压缩比例写成整模省内存比例。

`make_projection` 默认 BF16，Q4 提供者显式注入，并检查实际选中的矩阵。后端不支持时默认报错，使用者显式允许时才提示回退并记录实际精度；不会掩盖内核运行错误。库接口无个人路径或自动编译依赖。CPU 投影、ID 映射与回退单测通过；硬件加速证据仅覆盖这台 Spark。其他 tokenizer 须提供自己的词表；其他 GPU/后端仍需独立验证。

本轮“BF16 基线”指**草稿输出头**，不是整模 BF16：target 仍为现有 NVIDIA NVFP4 Qwen 权重。greedy 一致性只针对该 target 的同路径串行输出；随机采样、长上下文、完整引擎、多请求吞吐以及既有 target prefill / eager BF16 drafter fidelity 问题仍未解决。新任务的 TPS 不能直接与 E4 原生 MTP 的 55.99 TPS 排名。
