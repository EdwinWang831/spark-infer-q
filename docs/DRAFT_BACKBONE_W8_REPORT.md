# E28：草稿 MLP 的 INT8 可运行，端到端收益尚不明确

2026-10-23 UTC，`PASS_E28_FIXED_DECODE`。五层DFlash2 MLP已接入原生SM121 W8A16内核：INT8权重、每输出通道FP32尺度、BF16激活/输出、FP32累加。attention、特征入口、动态卷积、归一化、selector保持现有精度，完整词表输出头仍为Q4。不是整个backbone全部量化；没有改target或训练预测器。协议见[事前方案](DRAFT_BACKBONE_W8_PLAN.md)，[脱敏完整证据](../results/e28/2026-10-23-draft-backbone-w8.json)包含每次计时和每步轨迹。

从原E25清单按预定family/language分层及加盐SHA选择8条旧工程回归root，英5中3，含问答、代码、数学、多轮和768/1,024-token长输入。没有根据速度挑样本，也不是新的独立测试集。每条各组4次、顺序交替，共64次正式计时、每组8,588个实际decode token。输入27～1,024 token，实际输出133～384 token；不能外推4K+长上下文或一般线上流量。两组都固定最多7个草稿、按EOS/cap裁剪，不调用预测器或动态预算。这些42.x不能与E25/E27不同任务集上的吞吐直接比较。

计时包含草稿及F1特征提取、target验证、commit和循环；排除prefill、首token、初态clone、正确性检查和落盘。预热时两组分别与串行target核对完整token、每个已提交logit及最终live state；正式计时另在timer外核对完整token和最终state。全部通过。它证明这些greedy轨迹的执行正确性，不是随机采样或通用模型质量评估。

BF16对照中草稿只占13.6800%，target验证占84.6307%。按本次草稿节时折算，对整段decode的直接时间贡献约0.94%；即使模块加速是真实的，整段收益也受此占比限制。接受率下降约0.1585个百分点，验证轮数增加16次（+0.6319%），抵消部分草稿节时。验证时间还可能受不同轨迹、频率、缓存及计时波动影响；这些观测不足以把全部差值因果归到量化误差。

## 存储与复现范围

MLP共294,912,000个参数；原始canonical BF16权重562.5 MiB，原路径另有375 MiB融合gate/up副本。INT8执行包含尺度295,270,400 bytes（281.59 MiB）。A/B保留BF16控制与原session，W8包是新增副本，本轮没有证明整机净省这些内存，也没有测量生产加载方式的峰值内存。当前adapter仍保留原始非融合权重；部署省内存需要另做权重生命周期处理和实测。

同一常驻worker PID、load_count=1、相同target/draft对象，三项任务均PASS；completed_jobs从93→96，failed_jobs保持5。没有重载权重，没有恢复MLP/混合预测器实验。仅GB10/SM121运行验证，不宣称其他GPU后端兼容。
