## 容量实现

统一入口的容量上限和默认值扩大到 131072。高于 64K 时复用已有 2048 行
raw QSA 索引环，完整 K/V、全部池化历史和绝对位置保留。本轮接入统一服务，
原索引内核归属及精确语义见 [E51](E51_BOUNDED_INDEX_REPORT.md)。

草稿加载时，将原始 Q/K/V 和 gate/up 参数改为已有融合矩阵的精确视图。
参数名、形状、dtype 和逐项数值都检查一致后再整体替换绑定。实际 GPU
allocated 减少 555745280 bytes，约 0.518 GiB。MLP 的既有 W8 格式与
Q4 草稿输出头沿用原配置。

1024 行 prefill 仍略超预算，因此四请求 128K 自动选择 512 行。
64K 配合 E44 扩展时继续使用 1024 行。启动提前准备共享输出头 Graph，
再测量每个私有槽，避免把共享头反复计费。首个 128K 槽单独预留 4 GiB
测量空间，完整准入继续计入镜像特征环、请求投影和至少 1 GiB 暂存余量。

## 完整索引参考

一条真实 131008-token 前缀，同期对照完整 raw 索引与索引环，均使用原始
512 行算术。256 个分块的完整 logits 和全部五层特征逐块精确一致。
最终比较全部已提交 K/V、池化历史、有效 raw 尾部、GDN 和 PLE 状态，
结果一致。完整前缀之后的 width 1–8、两种奇偶及部分提交，共 16 组，
比较完整索引 eager 与索引环 Graph。另有四组奇数／回绕分块和三组回滚。

随后四个私有槽分别填满四条中英文、代码及混合提示，保留所有完整 BF16
K/V。逐 token 生成 64 输出，再复用已填充前缀，运行真实 DFlash provider
与 SpeculativeBackend 的隔离动态控制。隔离控制包含草稿、预测、验证和
提交，原生 Scheduler 与 HTTP 由后续四请求阶段另行覆盖。

四请求公开 HTTP 通过原生 Scheduler 运行，流式与非流式各两条。四条输出
token、有效状态、特征和动态轨迹均与控制一致。128K 位置另外完成 16 组
Graph/eager 及部分提交核对。超容量拒绝、取消长请求、同 ID 新代复用和
旧句柄拒绝通过。

## 计时与内存

带观测的四请求完整 cohort 为 **474.68 秒**，工作量为 524032 输入加
256 输出 tokens。该时间包含 prefill、首 token、草稿、预测、验证、提交、
调度及事件。最终数值指纹在计时后获取。

四个隔离动态控制共生成首 token 之后的 252 tokens，约 8.25 秒，汇总
约 **30.54 tok/s**。该口径为串行适配器循环，排除 prefill、首 token、
原生 Scheduler 和 HTTP。它单独说明有完整 128K 前缀时的控制执行成本。

整轮验证的 peak allocated 为 **86.87 GiB**，peak reserved 为
**87.98 GiB**，主机 MemAvailable 最低采样 **17.58 GiB**。
reserved 峰值包含作业起点从前次失败保留的 allocator 空闲块，四份前缀
填满后的实时 reserved 约 87.28 GiB。启动预测与实测分别记录。

## 常驻服务与独立客户端

最终常驻服务使用默认四请求 128K、512 行 prefill、原始专家算子、BF16 KV
和动态 DFlash。独立标准库客户端的四条长请求共耗时 **475.44 秒**，
524032 输入加 256 输出 tokens，四条文本与 token usage 均匹配控制。
该时间包含完整 prefill 和 decode。

同时观察到四运行加四等待，第九个请求返回 429。起步时 pending 命令可
暂时多于四，稳定四运行／四等待状态单独记录。默认 30 秒准入等待沿用原值。
短请求取消的三个幸存者与各自重放一致，断连后的重放也一致。
128K 输入请求的刚准入取消、同 ID 复用和旧句柄拒绝由前述独立验收覆盖。

客户端结束后，19 个请求正常完成、2 个取消，失败请求与 worker 失败均为零，
运行、等待和在途流全部回到零。服务继续常驻。wheel 在独立环境安装，
仓库外 CLI 通过，全部生产 Python 文件与 GPU／服务快照逐字节一致，
上游许可证随包提供。本轮复用已加载会话，冷启动历史见
[v0.1](ENGINE_V01_REPORT.md)。

## 保留的失败与修正

首轮索引验证在构造 128K 提示时失败。固定重复次数给出的填充文本不足，
生成器已改为按实际 token 数扩充，并增加四种输入的 128K 回归检查。

首次四槽执行填满四份前缀并通过 16 组 Graph 检查，随后在隔离 DFlash
控制中触发分配器上限。验证器同时保留了四套 GPU 回滚快照和特征副本。
修复后将这些验证副本保存在 CPU，逐请求释放已完成控制的特征环，GPU 上
始终保留四份真实 K/V。四槽前缀、控制和 HTTP 均完整重跑通过。
两份失败原始记录与 traceback 保留在归档中。

模型 PID 和 target/draft 对象贯穿容量测量、数值验证、重跑及常驻服务，
`load_count=1`。本地 CPU 共 500 项，459 通过，41 项可选环境跳过。

证据覆盖四条合成提示与每条 64-token 输出。长请求共用串行 GPU 工作区，
动态预算继续采用冻结 E17/E29。长 GPU 合批、持续压力、长答案质量与
八路／1M 服务仍待验证。
