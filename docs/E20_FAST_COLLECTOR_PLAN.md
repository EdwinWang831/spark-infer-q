# E20：采集器加速验证方案

2026-10-22。用户要求先优化采集器，避免后续扩大训练持续等待标签。此次优化不更改Target/DFlash权重、七深度标签或正在执行的E17/E19封存源码。

## 已确认瓶颈

原E17完整510条学习提示生成175,825个completion token，采样32,128位置。10片总计202.10分钟，其中分词/prompt/逐token参考轨迹187.76分钟，占92.90%；原生和特征DFlash采样合计约10.90分钟。首要优化为参考轨迹，保留标签抽样及校准语义。[原始采集剖面](../results/e20/2026-10-22-original-collector-profile.json)。

## 固定方法

`collection_trajectory.collect_trajectory`将Target的固定8行投机验证用于采集参考轨迹，按实际接受前缀提交。使用连续缓冲区保留prompt及每一行已提交的12800维Target特征，不保留拒绝草稿或最终pending token的特征。采集时不依赖当前预测器的测试结果。

校准任务前8次转换保持串行，保留逐位置logits/状态快照。轨迹生成后仍在完全相同的均匀位置独立执行原生和带特征DFlash，核对proposal一致、保存相同137维输入和七条件标签。标签仍调用原`emitted_by_width`及相同EOS/cap契约。轨迹缓存与标签缓存隔离，每次请求均重置。

## 对照和门槛

- 固定8个不同训练root：外部人工英文/中文各1，代码英文/混合各1，提取中文/混合各1，1K/1.5K上下文英文/中文各1。任务仅来自E16/E17训练划分，按ID哈希事前固定，不读取独立测试标签。
- 输出上限分别为384、192、128；真实EOS提前停止。四条模拟校准工作负载，其余为训练工作负载。
- 每任务先独立serial/fast轨迹oracle，精确核对完整输出、整条已提交隐藏特征、完整已提交logits、最终有效GDN/QSA状态、校准快照及所有训练行。
- 再做3轮交替AB/BA配对，合计48次正式采集。每次都独立分词/prompt/采集，不使用跨请求prompt cache；跨模式oracle核对在计时外。
- 另有真实GPU cap=1、first-token EOS、cap=2和cap=9边界核对；CPU穷举覆盖每个拒绝位置、EOS、cap以及拒绝特征不能流入后续草稿上下文。
- 只有全部一致性检查通过，且完整采集计算的任务中位数之和得到正加速，才允许新学习采集入口使用。普通/加权预测器及其数据不因结果被重新选型。

## 计时、审计与运行边界

`trajectory_ms`包括分词、8行prompt、轨迹生成和所需特征保留；`collection_ms`另外包括抽样DFlash、特征/标签及校准成本核对。不包含一次性模型/缓冲区初始化、最终JSON落盘、跨模式oracle比较或模型加载。按同任务token数、三次中位数再求和报告整体加速，同时报告各语言/长输入/自然EOS及三轮原始总时间。

输出是采集计算耗时，不是模型服务decode TPS。八个任务不代表所有训练语料分布；启动前的方法和源码均由常驻作业SHA绑定，原始行对照和计时留档。导出器独立核对行级x/y/emitted、采样位置、请求已知特征及原始数据SHA，并按独立root报告bootstrap区间。

若门槛通过，同一个常驻作业还会调用真实`e20_collect`入口生成两条16-token smoke记录，核对新入口的SHA门槛、缓存重置及数据持久化。后续入口当前只支持train/calibration，拒绝test，使用独立新清单，不替换E17已经采完的数据或绕过封存选型。

模型沿用原常驻worker，load_count=1；队列等待当前不可恢复分片完成后优先执行E20，之后原E17/E19链继续。任何失败留档并阻止启用，不自动重试/放宽精确性门槛。GPU性能对照上限为384输出；入口可配置1024输出，但这不等于已验证1024输出的配对收益。
