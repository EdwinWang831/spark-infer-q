# E3 动态预算诊断方案

本方案在本轮完整生成与位置重放结果产生前固定。目标是区分“当前长度范围内可节省的空间小”和“在线策略未识别可节省的位置”，不以预算必须变化作为成功条件。

## 实测组与校准

- 保持已固定的 target、BF16 DFlash2、SM121 算子及原始 DeepInfer MTPVarlen 二进制。已知草稿 BF16 数值差异、target prefill 差异保持开放；prompt 继续走相同 decode 算术。
- 五组为逐 token、验证 1/2/3 个草稿、原生动态验证。fixed1/2/3 都先生成完整三个 proposal，再裁剪验证；没有改变本探针的四行执行布局和卷积分组。
- 复用之前八个任务作为回归与诊断输入，不能再称为未见测试集。每组每任务五次，按五阶循环 Latin square 轮换，每组各占每个运行次序一次，共 200 次计时。
- 另设六个与八个任务不同的校准提示，覆盖中英短答、JSON、代码、思考和说明。单例最多 192 输出 token，是否 EOS/截断如实记录。接受率逐深度统计，拒绝后的未观测深度不计失败；初始 Beta(1,1)，在线使用强度四的校准先验和原来的滞后更新。
- 所有六个校准 prompt 的起始真实状态都测四档验证/提交成本，每档三次，并测完整草稿成本。启动曲线取样本中位数。记录上下文行数，不宣称已拟合长上下文成本模型。

## 正确性与计时

先运行逐 token oracle，再为每个非 serial 模式独立检查已提交行的 logits、输出和最终有效状态。正式计时运行只在计时外比较最终输出和有效状态。每次运行使用新状态、新接受率历史和新运行成本估计器。

计时为 decode host wall-clock，经 GPU 同步，排除权重加载、prompt、首个已输出而待处理的 anchor、校准、状态初始化及 oracle 比对。所有模式按 EOS 停止，达到输出上限记截断。分别记录草稿、验证、提交与决策耗时，同时保留包含其他控制开销的整体 decode 耗时，分段之和不冒充整体耗时。

动态若选择零草稿则跳过草稿网络，但 target 仍捕获特征，以允许后续重新启用草稿。纯 serial 不需要这些特征，保留其实际成本优势。成本曲线中只对有草稿档位加入一次草稿耗时。

## 相同位置的四档重放

选取翻译、量化说明、思考代码三个任务，覆盖之前观察到的极短 EOS、混合接受和较高接受。这是有目的的诊断选择，不是随机抽样。对其**每一个**真实 serial 生成位置分别执行四档，各重复三次，轮换档位顺序。草稿始终来自相同已提交特征和当前 anchor。

每个动作检查已提交行 logits 与 serial oracle 一致，第一次重复额外用独立 serial replay 比较有效状态。零草稿动作也保留特征，其他动作使用同一个完整三-token 草稿的实测成本；动作耗时包含验证、选择输出、提交和特征追加。状态复制与 oracle 比对放在动作计时外。

由每个位置四档的动作中位耗时和真实输出步长构图，计算：

1. 在同一重放成本模型下，每种固定档位走完整个答案的成本。
2. 已知后续接受和 EOS 的最小成本路径，及其选择的档位。
3. 最好固定档位与该路径的成本比。

第二项使用未来信息，只是对当前四档动作空间的事后成本诊断，不是可部署策略、实测在线收益、DFlash 理论上限或多请求引擎上限。独立动作中位数不能完整复现实际连续运行的热状态和调度开销。不会将最优路径反向喂给在线策略，也不会用它改本轮校准先验。

## 结果解释

公开每任务的五组中位数、范围、整体中位耗时之和的比值、动态长度分布以及事后路径。五次重复不足以单独支持统计显著性或通用性能结论。若动态仍选满，结合四档对照和位置重放判断具体原因，保留负结果。

本轮不含原生 Qwen MTP、训练置信度头、随机采样、多请求批处理、长上下文或服务级性能；这些方向的潜力不能由本轮否定。复现入口为 `scripts/e3_budget_audit.py`，工作模块与源码摘要由 `budget-audit-ready.json` 固定。

后续术语更正：四行是上述实验的执行范围，不是已证明的训练硬限制。固定 checkpoint 的 `dflash_config.block_size` 实际为 8；其 README 的上游评测使用 4 行并注明当前 QSA 实现限制。本说明不改变已运行的四档方案和数据，也不代表已验证八行执行。
