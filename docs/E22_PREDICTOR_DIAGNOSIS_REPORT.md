# E22 预测器诊断与 CPU 运行时原型

2026-10-23 UTC。结论：MLP 原约 0.55% 的离线劣势，大部分来自标量 Python 执行；去掉该因素后，预测决策也没有展示超越线性的明确证据。应先保留快速执行基础，再改善决策泛化与目标，不应直接扩大参数量。

这是一轮事后探索分析：只读 E17/E19 冻结数据与模型，没有拟合、重新选型、修改原始结果或发起 Target/CUDA 计算。原独立 test 已用于分析，未来修改需要新的独立测试。

## 1. 分开执行开销与决策

用相同 E19 主机、输入、交错测得的 CPU 费用，固定概率，再改变两者所支付的费用并重新选择每个位置的宽度。

| 对照，基准为匹配 E17 线性头 | 离线相对效率 | 分组 bootstrap 95% 区间 |
| --- | ---: | ---: |
| 原 MLP，支付其原费用 | −0.5461% | −0.7234%～−0.3244% |
| MLP，费用统一为线性头 | −0.1244% | −0.3029%～+0.0990% |
| MLP，费用理想化为零；线性费用仍保留 | −0.0444% | −0.2241%～+0.1807% |

以同一线性效率为分母，按“先变决策、后变费用”拆分：决策项 −0.1244 个百分点，额外费用项 −0.4216 个百分点，合计 −0.5461%；额外费用约占观察差距的 77.21%。该份额依赖上述反事实路径，不是通用因果归因。改费用会改变动作，MLP 有 15/5,532 个动作发生变化，分析没有错误地假设动作恒定。

统一费用后，英文 −0.2371%（区间 −0.4195%～−0.0581%），中文 +0.0607%（区间跨零），mixed −0.1515%（区间跨零）。不能把总差距全部归结为实现，也没有证据说英文已全面改善。

## 2. 训练误差下降，没有转成测试优势

| 平均七深度 cumulative Brier，越低越好 | 线性 | MLP |
| --- | ---: | ---: |
| train，45,081 位置 | 0.0842314 | 0.0805558 |
| calibration，5,614 位置 | 0.0871240 | 0.0873897 |
| test，5,532 位置 | 0.0821484 | 0.0822623 |

MLP 的 train Brier 降约 4.36%，calibration/test 没有下降。第七个条件事件的 train NLL 0.30423→0.19665，但 test 0.32088→0.34993；test 的该条件仅 699 个有效位置，train 为 7,072。结果与更大的泛化差距一致；不能仅据此确定是容量、正则化、标签覆盖或优化预算哪一项造成。

两者距离共同费用下的事后最优预算仍有空间。用 aggregate-ratio oracle 的 Dinkelbach 剩余量计算机会损失（避免逐位置 token/ms oracle 错误），线性总损失为 1,885.51 token 等价值，MLP 为 1,906.22。线性损失约 78.65% 来自相对事后 oracle 验证过长；但 oracle 知道未来接受结果，这不能证明实际策略应统一缩短。MLP 比线性多出的约 20.71 中，约 18.61 来自验证过短这一项。

test 中 1,638 个零接受位置贡献线性约 40.44% 的机会损失。它们可指导**训练集**难例采集策略；不得把 test 错例直接回灌训练后再使用同一 test 宣称泛化。按 root 聚合，mixed 派生与原问题保持同组，不能当独立样本增加置信度。

本次 test 没有 context≥768 的位置，因此上述结论不能外推到长上下文。完整覆盖范围与分层数据见 JSON。

## 3. 成本模型偏差

读取完整 E17 在线 trace，选定头的 7,221 次验证/提交步骤中，冻结成本曲线的 MAE 为 2.160 ms，MAPE 为 3.70%；整体偏差仅 −0.116%，但宽度 8 的成本低估约 4.08%。这说明整体平均准确并不代表每个宽度都准确；是否修正能改善预算决策需要新的受控测量，不能将误差百分比直接当潜在提速。

代码审阅还确认：离线按当前位置切 short/long，原在线按请求初始 prompt 长度固定 bucket。此次在线检查没有跨 bucket 步骤，故不能用该差异解释本次结果；后续长上下文实验应统一这条契约。

## 4. 已实现并实测 CPU 加速原型

新增可选 [`NumpyMLPProgressModel`](../spark_infer_q/mlp_runtime.py)，使用同一组冻结权重与 float64，逐向量推理，保留输入转换、有限值检查、归一化/裁剪、tanh 及原概率校准。原始 MLP 和 E17/E19 封存源未修改，不自动替换执行器。

在 Spark 独立 CPU 进程中，用 calibration 前 256 个位置，9 轮轮转/反向顺序，预热后计单条完整 `predict`，排除模型初始化。NumPy 2.1.0，`OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=2`；没有导入 Torch 或占用 CUDA。

| 运行时 | 每次预测中位数 |
| --- | ---: |
| 原线性 Python | 0.051515 ms |
| 原 MLP Python | 0.335320 ms |
| 新 MLP NumPy | **0.011815 ms** |

小头自身加速 **28.38×**，绝非整模型 decode 加速。训练/校准/测试全部 56,227 位置的最大概率绝对差为 **7.77e−16**；在相同原费用和相同新费用下，两后端各核对 56,227 次预算选择，动作差异均为 **0**。浮点概率不是逐位相同；未来在线仍须独立核对输出、logits 和状态。

用本轮测得的新费用离线回放，MLP 相对本轮重测线性头仍为 **−0.0623%**。这里只是诊断性回放，没有新在线 TPS，不改变 E19 未通过门槛的事实。
