## 执行与存储

- 四份私有 GDN、QSA、PLE 和 KV 状态共用一次投影、路由、专家及
  hyper-connection 前向。分段状态操作保留各自的位置与偏移。
- 单个 arena 复用阶段间互不重叠的宽矩阵临时存储。主残差、归一化
  部分和、inject gates、专家激活及待消费的路由权重拥有独立存储。
  最终输出头只处理每请求末行。
- PLE 尾状态在其输入存储被复用前提交，随后恢复当前位置，最终
  commit 推进位置。完整状态与后续 Graph 检查覆盖了这一存活期变化。
- 同一个 DeepInfer 原生 Scheduler 在生成 prompt 计划时短暂进入
  PROMPT 模式，以公共 `chunk_checkpoints` 限制每请求块长。`finally`
  恢复 NORMAL 后执行、处理 MTPInfo 并提交原生输出。控制接口校验
  上游 revision、头文件和二进制 SHA256，decode 获得既有交错执行机会。
- `prefill_gpu_batch=True` 与 `prefill_batch_requests=4` 描述 prompt
  合批。decode 使用私有 Graph 槽和串行共享工作区，`gpu_batch=False`。
  prefill 采用 eager 算子执行，`prefill_cuda_graph=False`。

实现见 [batch provider](../spark_infer_q/prefill_batch.py)、
[workspace](../spark_infer_q/prefill_workspace.py)、
[native control](../spark_infer_q/prompt_batch.py) 和
[调度接入](../spark_infer_q/kaifra_speculative.py)。算术及缓冲字段来源见
[第三方声明](../THIRD_PARTY_NOTICES.md)。

## 公开服务验收

已部署显式四请求 prefill 合批配置。独立标准库客户端对完整服务验收通过。

- 四条 131008-token 长请求同时运行，各输出 64 tokens，文本和 usage
  匹配封存控制。客户端 cohort 为 356.387 秒，包含 HTTP、分词与监控，
  单独记录这一入口的完整耗时。
- 八条短请求观察到四运行加四等待，溢出请求返回 429。同一输入经
  等待队列和槽位复用后的输出及 usage 一致，该组客户端耗时 14.500 秒。
- 取消一个实际活跃请求，三个存活请求与独立重放一致。断开真实 SSE
  连接后，服务恢复空闲，随后重放一致。
- 验收后 21 个已准入请求中，19 个完成、2 个取消，worker failure 为 0。
  活跃请求、打开的流和待准入请求均为 0。常驻模型加载次数为 1。

公开配置的内存准入预测为 87.986 GiB，包含现有暂存预算。
`/health` 报告四请求 prefill 合批、4096 行工作区及 BF16 KV。

## 验证范围

结论对应同一 NVFP4 target、BF16 KV、四条合成 131008-token 输入及
每条 64-token greedy 输出。四请求完整耗时与 per-request 首 token 的
取舍按实测报告。持续压力、更长输出和跨模型泛化需要各自的验收。
