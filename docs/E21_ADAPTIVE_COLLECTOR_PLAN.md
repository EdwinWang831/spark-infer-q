# E21：低接受率回退的自适应采集器

2026-10-22。E20固定8行轨迹通过全部精确性检查，8任务完整采集计算加速1.2707×，但其中一条中文任务中位耗时增加22.1%。因此不将固定宽度版本作为后续推荐入口，保留完整正/负结果，另验证自适应版本。

## 固定控制器

沿用E20的轨迹、特征缓冲区、抽样与标签代码，只给轨迹草稿添加`BudgetedTrajectoryDraft`适配器。使用已封存的E16 F1小头及其成本曲线，不训练或读取E17/E19测试结果。

每次轨迹请求先做4次单行推进，测量当前单行实际成本。生成草稿前，利用此前步骤的条件接受估计比较带/不带草稿的预计成本；需要草稿时，再用F1的137维输入/七个累计概率选择验证前缀。若选择单行但此前已经生成草稿，下一步的已知纠正token还能核对上一轮第一草稿，更新历史接受估计；这不是当前或未来Target信息。

控制器在最多8个已生成草稿的历史窗口中累计实际推进量/耗时。至少4次草稿步骤后，若效率不及当前单行效率的98%，回退16个单行步骤，再允许尝试。基于概率成本判断连续跳过时，也至少每16次跳过重新尝试，避免一直停留在过时估计。请求开始时重置所有缓存、历史和计数。校准任务原有的前8个逐位置快照先照常生成，再进入这个控制器。

这些常数在E21 GPU作业入队前固定；没有按独立测试调参。所有控制只改变计算分组，不改变目标greedy轨迹、Target/DFlash权重、采样位置或训练标签。

## 六任务确认与门槛

保留E20首个英文384-token任务和退化的中文384-token任务；另外按新ID哈希预先选取四个未参与E20的训练root：外部英文/中文各1（cap192）、混合语言代码1（cap192）、中文长上下文1（cap128）。共6个不同训练root，前三轮配对产生36次正式采集。新四条只是采集器确认问题，不是新的预测器测试集或泛化用户流量。

沿用E20的全部输出、整条已提交隐藏特征、完整committed logits、live state、校准快照和训练行精确比较，以及EOS/cap边界核对。另要求：

1. 六条整体完整采集计算加速>1。
2. 四个新root的整体加速>1。
3. 已知中文退化任务中位耗时增加不超过5%。

不通过则保留负结果，不生成可启用的新入口证据。通过后实际调用`e21_collect`生成两条16-token记录，核验数据保存/来源SHA。入口只接收train/calibration，E17/E19封存链及已有数据不替换。

`e21_validate`运行源、E16小头JSON和原始先验文件均纳入SHA。报告中继承的`verification_width=8`表示helper的最大宽度；实际宽度由适配器返回的前缀决定。轨迹`draft_calls`是草稿协议入口调用数，包含直接返回空前缀的跳过调用，不能当作实际DFlash骨干执行次数。

计时边界、每任务中位数之和、独立root bootstrap和独立CPU行一致性审计沿用E20。结果属于单请求greedy采集计算，不是服务decode TPS，不包含最终JSON落盘及额外跨模式oracle核对。
