# 提议：低位宽筛选加精确复核的 target 输出头

状态：**PROPOSED，尚未执行，没有新的 GPU 结果。** 实际排期时再分配 E 编号。

## 动机

每个验证 step 都要完整读取一次 target 输出头：248,320 × 2560 的 BF16 矩阵，共 1,271,398,400 B（E2 model-budget 记录）。按标称 273 GB/s 计算，下限约 4.7 ms。[E9](E9_DECODE_PROFILE_REPORT.md) 中“target finish”（最终处理和输出头等）约占采样 decode 的 8.35%。greedy 验证只需要每行的 argmax，如果能少读这块矩阵且 argmax 保证不变，就是不改输出的 decode 优化。

## 做法

1. 对每个验证行，用低位宽副本算出近似 logits，并按 [`logit_bounds`](../spark_infer_q/head_screen.py) 给出每个 token 的严格误差上界。上界覆盖三部分：量化误差（‖w−q‖₂·‖h‖₂）、精确路径与近似路径的 FP32 累加误差、精确输出的 BF16 舍入。
2. 保留所有“近似值 + 上界 ≥ 最佳下界”的 token。被排除的 token 一定严格小于某个已保留 token 的精确值，所以精确 argmax（并列时取最小 ID）必然在候选集里。
3. 只对候选 token 用原 BF16 头的相同算术计算精确 logits，再取 argmax。遇到非有限值，或候选数超过上限，就退回完整输出头。

## 为什么是 Q8 而不是 Q4

严格上界必须按最坏情况算，比典型误差大约 √H 倍。合成模拟（[`scripts/head_screen_bound_sim.py`](../scripts/head_screen_bound_sim.py)，Gaussian 行、H=2560、group 32）：

| 副本 | 典型误差 / logit 标准差 | 严格上界 / logit 标准差 | 保留的 token（按 248,320 词表换算） |
| --- | ---: | ---: | ---: |
| Q4 | 0.063 | 3.95 | 约 248,196，几乎全部保留 |
| Q8 | 0.0037 | 0.23 | 约 25 |

Q4 的典型误差与 E6 实测的 Q4 草稿头 logits 相对 L2（8.32%）量级一致，但严格上界下几乎不能排除任何 token，所以**不能用 Q4 做精确筛选**；只有放弃精确性、另设质量门槛时它才有意义，不属于本提议。真实 logits 在顶部更集中，候选数需要在实际捕获的 hidden 上测量。

## 预期幅度（条件估算，不是预测）

- Q8 group 32 副本：权重 635,699,200 B，FP16 scale/offset 79,462,400 B，加两个逐行范数约 2 MB，合计约 717 MB。
- 每步少读约 556 MB。按标称带宽约 2.0 ms，相对 E8 未采样平均 step（73.697 s / 1,021 步 ≈ 72.2 ms）约 **2.8%**。前提是输出头确实受带宽限制，且 Q8 kernel 达到相近的带宽。
- 代价：常驻内存增加约 717 MB；需要新的 Q8 GEMV 后端（E6 已注明 Q8 需要新增后端）。因此优先级低于整步 CUDA Graph 和草稿 backbone 精度。

## 事前门槛（执行前冻结）

1. **上界有效性**：在大量真实验证行上，实测的 |精确值 − 近似值| / 上界 ≤ 1，并记录最大比值。累加单位按实际 kernel 校准；只要有一例越界，就停止所有“精确”表述。
2. **子集算术一致**：只算候选行时，原 BF16 头 kernel 的结果必须与完整计算的对应行逐 bit 相同；否则 argmax 只能保证在上界意义下一致，不能称为与现行路径逐 bit 等价。
3. **端到端**：完整生成的输出 IDs 和有效状态与现行路径一致。这条路径不再算出全部 logits，oracle 改为核对 token 和状态，诊断运行另外计算完整输出头做对照。
4. **性能**：每步候选数的分布、退回完整输出头的比例、实测节省时间；完整 decode 配对 A/B 的收益低于噪声时不接入。

## 边界

只适用于 greedy；随机采样需要完整分布，必须走完整输出头。不改 checkpoint 或 target 权重；低位宽副本只用于筛选，不会进入输出。合成模拟只说明上界的松紧，不代表真实候选数。

## 参考实现

[`spark_infer_q/head_screen.py`](../spark_infer_q/head_screen.py) 提供 `rounding_gamma`、`logit_bounds`、`screen` 和 `exact_argmax`，均为标准库 host-only 代码。单元测试用逐步 FP32 累加加 BF16 输出舍入的纯 Python 模型作为“精确”路径，验证上界成立、筛选后的 argmax 与完整 argmax 相同、并列时取最小 ID，以及各种退回情况。测试不在 GPU 上运行。
