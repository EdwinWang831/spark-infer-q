# E3：动态预算的四档对照与位置重放

**当前策略没有兑现局部动态选择的空间。** 200 次完整生成计时中，验证 1/2/3 个草稿相对逐 token decode 的汇总比值分别为 1.278×、1.597×、1.794×；原始 DeepInfer 动态预算为 1.799×，475 次决策仍全部选 3 个草稿。独立位置重放显示，在“量化说明”任务中，知道未来接受结果的选档路径可将模型成本进一步降低约 20.3%，但这不是在线实现的收益。

证据：[公开 JSON](../results/e3/2026-10-20-budget-audit.json)。[事前固定方案](E3_BUDGET_AUDIT_PLAN.md)和[上一轮数值边界](E3_FOLLOWUP_REPORT.md)保留独立。

## 完整生成实测

保持同一 target、BF16 DFlash2 和 DeepInfer 预算二进制。八个任务复用上一轮输入，是回归和诊断，不再称为未见测试集。每任务五组各五次，按循环 Latin square 轮换，每组各占一次首至末位，共 200 次计时。先验来自另外六个提示；六例均自然 EOS，输出为 2～59 token，没有触发预设的 192 token 校准上限。

固定 1/2/3 表示验证的草稿数，另有一行 anchor；草稿网络仍一次提出三个 token。动态使用原始 MTPVarlen，接受率保留原来的滞后统计，运行成本按实际草稿、验证和提交总耗时更新。

| 任务 | 输出 token（含 EOS） | 逐 token ms | 固定 1 ms | 固定 2 ms | 固定 3 ms | 动态 ms |

| 加法 | 3 | 86.55 | 61.79 | 70.01 | 75.60 | 74.58 |
| 首都 | 8 | 290.31 | 250.55 | 196.06 | 138.41 | 140.36 |
| Python 加法 | 18 | 716.58 | 554.67 | 387.30 | 346.49 | 349.41 |
| 翻译 | 2 | 44.07 | 64.93 | 68.71 | 70.66 | 68.99 |
| JSON | 19 | 759.41 | 560.38 | 395.76 | 355.82 | 347.78 |
| 量化说明 | 54 | 2244.63 | 1973.59 | 1779.08 | 1688.72 | 1663.23 |
| 思考算术 | 78 | 3277.52 | 2529.44 | 2089.09 | 1924.14 | 1883.56 |
| 思考代码 | 113 | 4756.50 | 3529.84 | 2636.77 | 2187.92 | 2240.71 |
| 各任务中位数之和 | — | 12175.57 | 9525.20 | 7622.77 | 6787.77 | 6768.61 |
| 汇总 decode 比值 | — | 1.000× | 1.278× | 1.597× | 1.794× | 1.799× |

所有八个请求自然 EOS。200 次计时的完整输出和最终有效状态与 serial 逐 bit 一致；另有 32 次非 serial 正确性运行，逐个已提交行的 logits、输出和最终有效状态一致。六项字面/格式属性检查通过；代码没有执行，不据此给出通用质量评价。

时间为同步 host wall-clock decode，不含加载、prompt、首个已输出 anchor、状态初始化和 oracle 检查。原始样本及每任务 min/max 均在 JSON。整体耗时包含特征追加、控制和统计等开销，不把分段耗时之和当作整体耗时。五次重复不能单独支持显著性或通用性能结论。

动态与固定 3 的汇总差异约 0.28%，而两者每次都选相同长度，不能称为策略收益。短加法的最佳固定档位是 1；极短翻译的所有投机档位均慢于纯 serial。全局总量上固定 3 最快，不代表每个请求或位置都应选满。

## 为什么更充分校准后仍选满

六个独立校准提示得到逐深度条件先验 `[0.7377, 0.6818, 0.7586]`；Beta 计数分别为 success `[45,30,22]`、trials `[61,44,29]`。拒绝后的未见深度没有计失败。

| 验证总行数（含 anchor） | 启动成本 ms | 模型预期输出 token | 预期 token/s |
| --- | ---: | ---: | ---: |
| 1 | 43.18 | 1.000 | 23.16 |
| 2 | 62.30 | 1.738 | 27.89 |
| 3 | 65.94 | 2.241 | 33.98 |
| 4 | 68.09 | 2.622 | 38.51 |

草稿独立中位成本为 14.42 ms，已且仅已加入有草稿档位。预算实际还使用运行反馈修正；上表是启动曲线的诊断，不冒充其每次运行的完整内部估计。

在这个平均接受率和成本模型下选满是合理的。增加校准提示仍不能让平均历史率识别当前局部难点。缩短到 1/2 个草稿也不会减少草稿网络的计算，验证从总行数 2 增至 4 仅多约 5.79 ms。

## 位置重放揭示的空间

对翻译、量化说明、思考代码三个有目的选择的诊断任务，在全部 166 个 serial decode 位置重放总行数 1/2/3/4，各测三次，共 1992 个动作。所有已提交 logits 与 serial oracle 一致；每个位置每档第一次重复另做有效状态对照，共 664 次，均一致。

每个动作的步长由真实接受和 EOS 决定；动作成本取独立重放中位数，再用动态规划计算已知未来的最小成本路径。零草稿动作仍保留 target 特征，以允许后续重新启用草稿；其成本不能直接替代纯 serial 模式的实测成本。

| 任务 | 重放模型下最佳固定总行数 | 最佳固定成本 ms | 事后选档成本 ms | 固定 / 事后成本 | 成本减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 翻译 | 1 | 43.24 | 43.24 | 1.000× | 0.0% |
| 量化说明 | 4 | 1664.62 | 1327.33 | 1.254× | 20.3% |
| 思考代码 | 4 | 2204.27 | 2127.05 | 1.036× | 3.5% |
| 三任务成本之和 | 各自最佳固定 | 3912.13 | 3497.63 | 1.119× | 10.6% |

翻译的最佳固定动作本来就是零草稿；相比一直选满的重放成本 67.90 ms，零草稿为 43.24 ms，但知道此处即将 EOS 属于未来信息。

量化说明的事后路径包含 11 个零草稿动作，这 11 个位置若启用完整草稿都会在第一个草稿处拒绝。这直接给出可研究的局部机会：在付出草稿成本前识别低接受位置。思考代码的空间明显较小；其一个零草稿选择还涉及后续路径对齐，并不能解释成当前第一个草稿一定拒绝。

三任务事后路径共用总行数 1/2/3/4 分别为 13/6/7/30 次。JSON 保留每个位置四档成本、步长和完整路径，可以检查这些选择。

**这些数字使用未来接受和 EOS，以及独立动作的中位数，是成本模型内的事后诊断。** 不是在线加速实测，也不是无噪声的绝对上限。它没有计入新预测器的开销，不能完整重现连续执行的热状态；最佳路径还可能受计时波动影响。不能将 1.254× 直接乘入已测 1.799× 宣称新的端到端速度。

所有重放动作使用对应 serial 前缀捕获的特征；事后路径没有作为新模式连续执行，其不同档位组合下的后续草稿特征也未另做逐 bit 对照。这也是路径数字只能作为诊断的原因；未来在线策略仍必须独立通过完整生成和有效状态验证。

## 工程结论与下一步

当前原生预算桥接没有更细的上下文置信度信息，只用平均历史接受率；本轮看到的潜力主要来自局部差异，而非“把历史统计样本加多”即可自动兑现。

下一步应建立分开评估的两级决策：先在生成草稿前判断是否值得支付其开销，再在草稿可用后分配验证长度。前者需要使用决策时已知的信息，例如最近 target 特征和过去接受记录；后者可以研究草稿分数，但分数必须用独立数据校准，不能直接当接受概率。训练、校准和新测试输入必须分离，不能用本轮事后标签训练后再在原任务上报未见收益。

先验证 greedy 输出与状态，再测同条件固定档位、原始动态和新策略的完整耗时。随机采样若引入当前草稿置信度，需要另行证明调度依赖与采样正确性，不能绕过原先的滞后约束。多请求之间的预算分配仍是单独未测的潜力，不能被本轮单请求结果否定。

## 资源与复现

- 本轮 BF16 测试 Torch allocated/reserved 峰值 72.9230/72.9531 GiB；结束前主机可用样本约 28.29 GiB，不是全过程最小值。
- cgroup 最终 events 全零，但不覆盖所有 CUDA 统一内存。最长有效提交位置为 185，分配容量 1536，不宣称验证了长上下文容量。
- 仅使用原有实验容器。运行结束释放模型，随后停止容器；未部署服务或重启旧服务。
- 期间 SSH 跳板读取超时，切换到同一主机的直连路径后取回完整 PASS 证据。GPU 实验没有因此重启，未发生本轮构建或模型执行失败。
- 本地 43 项标准库测试通过，运行时源码摘要逐项核对。权重、第三方源码、二进制、wheel 和原始日志均留在私有区。

入口为 `scripts/e3_budget_audit.py`，使用原 `e3_run.sh`、同一外部环境和 checkpoint，`--repetitions 5`。将公开 JSON 的 `harness_sha256` 按原目录部署并保存为 `budget-audit-ready.json`；入口加载后核对摘要再导入工作模块。公开导出使用 `python3 -m scripts.e3_export_budget_audit <private-json> <public-json>`，验证摘要、运行顺序、正确性标记和路径模型后拒绝私有绝对路径及 NaN。
