# E38：专家两组输入复用权重，未通过性能门槛

2026-10-24。**本候选不采用，继续保留 E36 prefill。** 同一专家的两组输入共用权重加载和解包，在全部组件正确性检查中保持精确，但完整 MoE 的 CUDA-event 成本增加 **3.934%**；没有新增 prompt tok/s 或 decode 收益。

## 真实路由与候选

沿用 E37 四条封存输入 code512、english64、mixed512、JSON128，采集全部 192 层、583,680 个 routed pairs。现有实现已经聚合同专家输入，新增 grouping 不是本轮改动。

| 输入 | 原16行 item | 候选32行 item | 权重阶段重复加载次数可减少 |
| --- | ---: | ---: | ---: |
| code512 | 22,815 | 16,031 | 29.74% |
| english64 | 6,653 | 6,294 | 5.40% |
| mixed512 | 24,011 | 17,550 | 26.91% |
| JSON128 | 10,090 | 9,058 | 10.23% |
| 合计 | 63,569 | 48,933 | 23.02% |

这是根据真实路由计算的内存阶段计数，**不是已测 DRAM 字节、带宽或速度**。四条采集输出的完整末行 logits/五层拼接特征 hash 与 E36 一致。

据此冻结唯一候选：rows<256 直接调用原 MoE；较长输入使用32行 plan，不超过16行的 item 走原单组累加器，超过16行走双组累加器，两次 kernel 互斥过滤。双组共享 packed NVFP4 权重加载、FP4 解码和 scale 转换，保留每行原 K-block 顺序、BF16 输入、FP32 scale FMA、原 SwiGLU/F32 down 及 slot 次序。独立编译 SM121 扩展，没有修改全局算子或原权重。

## 正确性与完整 MoE 成本

人工路由检查十种行数1/15/16/17/31/32/33/64/128/512，连续/stride、F32/BF16 down，共40项，覆盖16/32边界、guard和两次Graph重放；另一个caller stream通过。人工路由刻意让专家看见指定行数，不冒充自然路由。

随后对四条真实输入的0/23/47层，共12份完整 MoE，比较 router logits、pick、wts、完整 act/y，全部精确。每份输入两种缓存条件、六轮 AB/BA、两模式，共288个CUDA-event区间、576次计时MoE调用。warm每区间3次，128MiB缓存扰动每区间1次；Graph捕获、扰动、检查在timer外，router/select/plan、路由专家、共享专家和写回在内。

| 12份输入各组中位数之和 | 原版 | 候选 | 成本变化 |
| --- | ---: | ---: | ---: |
| 热复用 | 43.290 ms | 44.935 ms | **+3.800%** |
| 128MiB缓存扰动 | 43.342 ms | 45.047 ms | **+3.934%** |

扰动条件六轮全部更慢。三个真实层的合计成本，code为13.092→14.252 ms（+8.86%），mixed为15.722→16.337 ms（+3.92%）。保持原实现的短输入控制分别有+0.22%和−1.03%的波动，不视为候选收益。扰动不等于证明缓存全部驱逐。

事前门槛是扰动条件成本至少减少5%、至少5/6轮更快、每份输入不能慢超过2%；本轮不通过。因此未运行候选的48层完整prompt A/B、后续decode交接或HTTP测试。穿插采集的完整前向在继续下一层前恢复原MoE，其输出hash一致，只证明观测过程未改变控制输出；不能称为候选整模状态验证。

## 为什么减少加载仍更慢

真实编译资源如下，均无 local-memory spill：

| 候选中的实现 | gate/up 每线程寄存器 | down 每线程寄存器 |
| --- | ---: | ---: |
| 单组16行 | 126 | 95 |
| 双组32行 | 168 | 128 |

双组累加器提高了寄存器需求，同时增加了互斥过滤的启动和调度工作。这些事实与净退化相符，但本轮没有隔离各因素，也没有测 SM/DRAM 硬件计数器；不能断言唯一原因、带宽饱和或所有权重复用都无效。

更值得检验的后续方向是 **CTA 内协作加载权重、每个 warp 保持16行累加器**，用共享内存流水换取复用，避免继续扩大单warp寄存器占用。这只是下一候选设计，没有已测收益；不重复本轮tile/warps参数扫描。
