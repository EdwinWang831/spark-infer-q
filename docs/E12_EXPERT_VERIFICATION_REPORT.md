# E12：专家信息有预测价值，当前历史特征尚不足以支持在线提速

2026-10-21。[预先冻结的方案](E12_EXPERT_VERIFICATION_PLAN.md) · [数据](../results/e12/2026-10-21-expert-verification.json) · [常驻执行器](RESIDENT_RESEARCH_WORKER.md)。

## 真实结果

完整 Qwen Target 和 Q4 DFlash 在 GB10/SM121 上加载一次，完成 12 个新 prompt、72 个 committed 前缀、576 组宽度对照、1,728 次正式验证计时。六个 prompt 拟合、六个 prompt 仅评估；各 prompt 第一个位置没有历史路由，因此所有模型的共同评估排除这些位置，train/test 各 240 个 action。没有随机拆分同一 prompt 的计时。

所有宽度的已提交 greedy logits、GDN/QSA/PLE live state 与 serial 一致；观察路径的全部 logits/features 与原路径一致；各宽度的路由等于 width8 的相应前缀。全部计时后的输出与 live state 检查通过。**没有执行新在线策略或完整请求加速对照。**

| 模型 | held-out mean absolute error | median absolute error |
| --- | ---: | ---: |
| M0：每宽度实测曲线 | 1.6710 ms | 1.3489 ms |
| M1：每宽度曲线 + context | 1.6830 ms | 1.3370 ms |
| M2：M1 + 本轮真实专家并集，仅离线 | **1.2425 ms** | **0.9644 ms** |
| M3：M1 + 上一个实际 width4 行为的专家并集 | 1.6422 ms | 1.3564 ms |

M2 相对 M1 的 mean AE 改善 **26.17%**，六个 prompt 配对 bootstrap 95% 区间 **12.36%–35.26%**；相对 M0 改善 25.64%。mean AE 的点估计跨过预注册 25% 门槛，但区间包含低于门槛的改善；不是“至少改善25%”的统计保证。median AE 相对 M1 改善 27.87%。测试中较长输入的那个 prompt，M2 仍从 1.748 ms 退化到 1.863 ms。

M3 相对 M1 仅改善 **2.42%**，相对 M0 改善 1.72%，median AE 相对 M1 反而略差。**真实专家信息有用，不意味着仅靠上一轮专家数量就能准确提前预测。** 当前并未训练神经网络路由预测器。

## 预测改善不等于 decode 提速

保持同一份冻结接受率先验，给各模型选择宽度，再用各 action 的实测 verify+commit 中位数及完整 DFlash 费用核算同前缀期望 token/耗时：

| 选择依据 | 相对 M1 的指标变化 | 30 个测试前缀中改选宽度次数 |
| --- | ---: | ---: |
| M0 | 0% | 0 |
| M2，离线真实专家输入 | +0.563% | 10 |
| M3，仅历史专家数量 | +0.092% | 2 |
| 直接知道真实 action 成本的诊断 | +1.277% | — |

M0/M1 均选 width5。M2 在 width4/5/6 间切换；真实成本诊断在 width3–7 间切换。这些是 **固定先验、独立 action 成本、同前缀的期望比值诊断**，不是 decode tok/s，不是完整路径的严格收益上界，也不包含可部署预测器的运行成本。它还使用了当前测得的 draft 成本；width1 的零 draft 计费对应“生成草稿之前就决定跳过”的动作，不能解释为完整草稿已经生成后能退还费用。

因此，这轮不支持直接投入复杂预测器或升级默认预算。下一步应先检验廉价的验证前信号与接受收益条件下的预算差异，再决定是否值得上线；不能把 26.17% 的误差改善宣传成速度提升。

## 专家足迹、计时与边界

- 同样 width4，各层专家并集之和为 1,003–1,562，verify+commit 中位数范围 50.37–64.52 ms；width8 对应 1,733–2,525 和 64.14–76.41 ms。不同上下文/任务仍可能有其他差异，范围不是控制所有变量后的因果效应。
- 正式计时使用未修改的 `WideTarget.run`；48 层路由复制与 CPU 提取在另一次观察执行中。观察/原验证耗时比中位数 1.0165，但不是严格配对的纯采集开销测量；不能直接当在线控制器成本。
- 三次重复的 `(max-min)/median` 中位数 **3.52%**、均值 4.23%、最大31.00%，已保留波动。真实成本诊断的约1.28%余量与这种噪声同量级，仍需在线重复对照。
- 实际 context 仅 **39–116 token**，每个 prompt 只观察前六个行为 step；名为 `long` 的任务是相对较长输入，**没有长上下文证据**。本轮也未覆盖 batch、树验证或完整输出质量。
- `union × pack_bytes` 是唯一专家 pack footprint，不是 DRAM 流量、缓存命中或实测带宽。没有新的硬件计数器证据。
- 原 loader 及原算子源有指纹校验；未叠加 E10/E11。采集源固定在本地实验提交 `733e9b7` 对应的 runner 上，raw manifest 记录实际源 SHA256；分析器另记录其自身及依赖 SHA256。
- 全过程约672秒，其中本地权重读取/缩放解码与加载约394秒。没有网络下载模型。最初误选另一份已有权重目录的启动在指纹检查处拒绝，没有采集样本；失败日志与记录保留在私有原始目录。
- 峰值 CUDA allocated **75.018 GiB**、reserved **75.838 GiB**，包含多份对照 state。OOM / OOM kill 均0。cgroup memory.current 不是全部统一内存驻留量，不能替代 CUDA 和整机内存核算。

## 推进决策

1. 保留本轮正向证据：真实专家足迹对成本预测有增量；保留负向证据：仅上轮数量不足，当前冻结先验的预算余量很小。
2. 不把 M2 直接上线，不启动大型路由预测器训练。后续先利用已经支付的草稿特征或更细历史路由，要求新增开销低于可获得的收益；采用新的 prompts 检验，避免在这六个测试 prompt 上持续调参。
3. 若要做 post-draft 选择，明确草稿费用已经支付；若要决定是否生成草稿，只能使用 pre-draft 特征。接受率变化与成本模型变化分开消融。
4. 后续使用常驻研究 worker，复用已加载模型；在线改变预算后，仍须完整 greedy/state oracle 和配对 decode 实测才能声称提速。原默认路径不变。

## 常驻切换验收

采集结束后完成一次必要的常驻切换，见 [复用证据](../results/e12/2026-10-21-resident-reuse.json)。新 worker 连续执行中英文两个 probe：同一 PID、同一个 Target 对象、同一个 DFlash 对象、`load_count=1`；两次 logits/commit-state 对照均通过。任务结束后保持 READY，模型继续驻留，没有停止容器或释放 session。两次 probe 不计入上述性能样本。完整 CPU 测试运行93项，91通过、2跳过。
