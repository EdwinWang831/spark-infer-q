# E27：线性执行优化与因果成本修正

> 已完成：见[实际decode报告](E27_LINEAR_COST_REPORT.md)。实时费用修正未确认收益；纯NumPy执行约+0.60%，重复敏感性区间跨零，默认策略不变。以下保留事前方案。

用户决定暂缓MLP/混合路线，回到线性。E26仅完成2条提示、18次计时后暂停；改线性时在第三条串行参考完成后的保存边界取消，未恢复任何混合/MLP分支。该操作令worker记录一次预期的管理性失败，已单独留档，不当成算子错误或性能结果；常驻PID319、load_count1保留，worker回到READY。E26源码/模型和部分数据保留，不把其未完成测速当结论。

本轮所有方案共用原E17已选线性权重、归一化及概率校准，不训练新模型：

1. 原Python线性＋冻结成本曲线。
2. 同权重float64 NumPy线性＋同一冻结成本曲线。
3. 同NumPy线性＋实际已支付草稿/特征/预测时间＋只用过去步骤的验证成本修正。

第三组在选择预算之前测得本轮已经支付的draft/features/predict耗时，加上历史调度开销估计；它对每个宽度都计入已支付费用，包括width1。验证/commit的费用修正只能使用过去已完成步骤，不能看到本轮验证结果。每个请求内分别为short/long保留最近32个样本，以两参数线性残差（截距和归一化宽度斜率）、ridge8收缩到原曲线，修正幅度限制在原费用±20%，再保持曲线单调。每次生成重新冷启动，不能跨重复偷带学习历史。调度开销估计用过去观测的0.8/0.2平滑，参数事前固定，不看test调参。

这是一个组合的成本控制器候选，不能仅凭三组对照将第三组收益全部归因于草稿计时或验证费用中的某一项。第二组用来单独区分后端收益，第三组的预测权重和概率仍与其一致。新增模块不覆盖旧封存源，不调用MLP或混合模型。

预检读取原10,054个calibration位置，验证原Python和NumPy概率最大差小于1e−12，并在两组实际CPU费用下核对预算动作完全一致；另测完整predict费用和新提示实际tokenizer容量。没有拟合、calibration选择超参数或新增Target调用。

新12条提示在运行前固定（英8中4），来源沿用OASST1、MBPP、GSM8K与自编采购表；自然root排除E17/E23/E24/E26，做normalized/trigram(.82)提示去重。长输入768/1024属于熟悉的合成格式，不外推自然长文档或陌生模板。许可延续E24；无权重下载。

三组每条重复3次，共108次计时，正反与循环轮换顺序。各组先对串行参考核对完整token、提交logits和live state，计时后另核对token和live state。计时覆盖全部实际draft、特征、预测、调度、验证、commit与循环；prefill、克隆初态、正确性检查和落盘不在decode时间内。384输出cap包含首token，统计decode token按completion长度减1。

主指标为每组总decode token/总墙钟decode时间。按12个root聚类保留各重复做4000次配对bootstrap；区间跨零不确认收益。12个受控场景不代表一般用户流量，也不与其他实验任务集的绝对TPS直接比较。
