# E11：量化投影与 BF16 大矩阵乘优化结果

2026-10-21。[方法](E11_PROJECTION_PLAN.md) · [微基准数据](../results/e11/2026-10-21-projection-micro.json) · [完整生成数据](../results/e11/2026-10-21-projection-integrated.json) · [可选执行器用法](E11_PROJECTION_USAGE.md)。

**结论：正确性通过，整段收益不足以替换默认路径。** 量化投影的显式分片归并在独立微基准中有局部收益，但完整动态生成的整体 decode 仅 **45.45→45.73 token/s（+0.62%）**，完整请求耗时减少 **0.64%**；四轮中一轮 decode 略慢，部分任务退化。BF16 分块调整没有稳定收益。E8/main 默认路径不变，候选仅作为可选研究执行器保留。本轮已结束，没有追加调参或宣称相对原生 TensorFold 的新排名。

## 实现与筛选

读取与 E8 相同的已固定 checkpoint（config/index SHA256 均核对），使用真实权重及合成 BF16 带行间距输入。覆盖 BF16 完整词表输出头、hyperconnection down/up，以及 MXFP8 GDN in/out、共享专家 gate/up 和 down。GDN out 的 `(N,K,split-K)=(2560,6144,8)` 也覆盖模型中相同形状的 attention 输出投影。

BF16 使用原外部接口对照 N 分块、warp 数和流水级数，固定 BK=64 和原 split-K，包含 HC down 的 FP32 输出。MXFP8 对照原 cluster 归并、显式 partial buffer＋归并 kernel、单 block 内归并，保持原 split-K、分片计算和加法顺序。

微基准：筛选采用 1/3/4/6/8 行，独立进程复核采用 3/6/8 行并更换所有输入种子。6 轮平衡顺序，每轮 3 次 CUDA-event 区间；同层复用和每次遍历读写 128 MiB 缓冲两种缓存条件。共 **207 组变体完整输出/保护行精确检查（含原路径控制）**、**7,452 次 event 区间**。所有对照输出精确一致，无被隐藏的数值失败。

| 独立复核、候选/原路径速度因子 | 同层缓存复用 | 128 MiB 缓存扰动 |
| --- | ---: | ---: |
| BF16 输出头，流水级数 3→4 | 1.0106× | 1.0027× |
| BF16 HC down，同上 | 0.9696× | 0.9839× |
| BF16 HC up，同上 | 1.0101× | 1.0046× |
| MXFP8 GDN out，显式 partials | **2.0741×** | **1.0557×** |
| MXFP8 共享 gate/up，显式 partials | 1.3941× | 1.0121× |

BF16 不推进默认修改。仅将两种选定 MXFP8 形状的显式 partials 推进整模对照；其他形状与专家核不变。缓存复用的局部 2.07× 不是整模提速。128 MiB 遍历是缓存扰动，不能证明所有缓存行均被驱逐；event 区间也包括主机发射造成的空隙，不是纯 kernel 硬件计时。

`ProjectionRoute` 复用原 `qmmf` 二进制，为选定的 1–8 行输入提供预分配、连续的 FP32 scratch，使原扩展选择计算分片后顺序归并的路径。两个共享池合计 **819,200 bytes（800 KiB）**，请求前分配，无新增目标权重量化、激活量化或新 CUDA 扩展。池的所有权仅适用于当前串行请求和有序 GPU stream，不能直接用于重叠请求。

## 完整生成：同次加载、80 次正式计时

沿用 E7/E8 十条已见短上下文任务，每任务/模式完整预热，然后在一次模型加载内按任务和重复交替 AB/BA，每模式四次。两模式均采用 rows8 prompt、完整词表 Q4 草稿头、BF16 backbone/selector/KV 和原 E6 校准，运行时动态预算反馈保持启用。

以下耗时是各任务四次中位数再求和，**不是单个请求延迟**；decode 按实际输出 token 数减一加权。

| 十条任务整体 | 原 cluster 路径 | 显式 partials 候选 | 变化 |
| --- | ---: | ---: | ---: |
| 加权 decode token/s | 45.445 | 45.727 | +0.62% |
| 完整请求耗时之和 | 22.624 s | 22.480 s | 耗时减少 0.64% |
| wire TTFT 之和 | 4.205 s | 4.169 s | 耗时减少 0.85% |

自然完成八任务 decode 因子 1.0104×；两个 capped256 任务为 1.0035×。四轮整体 decode 因子分别为 **1.0108×、1.0189×、0.9985×、1.0087×**；不能声称稳定或统计显著的提速。LaTeX 任务的中位 decode 因子约 0.9796×，中文散文、even 和长代码也略慢，完整逐任务范围保留在数据中。

计时基线有与候选相同、但关闭优化的 Python 路由包装；它没有改变原 kernel 的选择。历史 E8 没有该包装，本轮没有另测包装开销，不能把与历史 E8 的跨轮差异当作新收益。

## 正确性、工作量与结论边界

- 每任务独立运行 serial rows1 参考，再比较四组原 E8 路径和 fixed7/dynamic7 两组新路径。共 **70 次完整预热**，其中 **60 组完整生成 logits/最终有效状态对照**通过，检查 **5,022 行已提交 logits**。新路径占 20 组/1,674 行，原路径控制占 40 组/3,348 行；不是 60 组新路径独立实现 oracle。
- **80 次正式请求**的完整 IDs、prompt IDs、客观答案检查和响应后独立有效状态检查全部通过，回归 E7。散文仍没有独立语义质量评分，两个长输出任务仅检查 256-token 前缀。
- 运行时预算发生变化：原路径宽度 3/4/6 的步数为 **32/241/743**，候选为 **34/357/635**。原路径共验证 **5,498 行**、候选 **5,328 行**，均提交 **3,348 行**；投机步数分别为 **1,016/1,026**。不能将工作量变化与纯 kernel 成本改善混为一谈。
- 主机计时的 target 验证总耗时为 **61.966→61.083 秒**，草稿为 **10.468→10.674 秒**。这些是全部 40 次请求的分段总和，与上表每任务中位数之和不同。主机分段也不是 GPU kernel 的独立累计时间。
- 观测提案接受数/观测数为 **2,362/4,448** 和 **2,353/4,267**。预算宽度不同导致观测位置不同，不能据此宣称草稿质量或接受率被内核修改改善。
- CUDA 峰值 allocated/reserved 约 **72.965/73.404 GiB**。OOM/OOM-kill 实查为 0，实验 worker 已退出。本轮只有模型 worker 使用 GPU，但主机仍有常驻 CPU 服务，不声称全机完全隔离。

本轮排除了一个较大的缓存微基准收益被直接外推为模型收益的可能。简单 BF16 调参与本次 MXFP8 归并调整都不足以支撑默认升级，继续投入同类调参的优先级降低。真实多请求 GPU batching 尚未完成，是后续更值得验证的吞吐方向；单请求延迟改善仍需要独立证据。

## 来源与复现

微基准执行源固定在 `f59ec53`；整模执行源固定在 `3349790`。公开数据包含 runner、外部源、扩展及研究环境文件的 SHA256；导出器验证形状、种子、重复完整性、计时输出、oracle 和路径计数。`e11_micro_export.py` 与 `e11_integrated_export.py` 生成脱敏结果。上游源码、完整权重和私有环境路径不入库。

预检最初查看的另一个本地 checkpoint 被 header/payload 一致性检查拒绝；在任何该 checkpoint 的 GPU 执行前，切回 E8 已固定的 config/index。没有混用不同权重的性能结果。沿用当前驱动权限，没有重试修改硬件计数器权限，也没有新的带宽/SM counters。

本轮是一轮完整加载、四轮配对计时和十条已见输入。没有新的原生 TensorFold 重测、多请求吞吐、长上下文、随机采样或官方 BF16 草稿 fidelity 结论。
