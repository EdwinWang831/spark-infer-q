# E34：筛选头候选压缩与精算固定容量 Graph

固定 E33 的 INT8 辅助头、定向 FP64 界、cap2048、原 BF16 BK64/SK1 精算及回退规则。只改变候选存储和执行组织，不训练、不改预算、不重载模型，也不修改另一个工作区的 K4 源码。

候选使用 GPU tile 计数和有序压缩写入固定 2048 槽；精算通过设备端候选数屏蔽空 tile。近似头、界、压缩、精算、argmax 和状态归约一起捕获。主机只读取一次小状态，必要时执行原完整 BF16 回退；因此不是全异步执行。

先检查1～8行、零并列、NaN/Inf/越界、强制容量回退、tile边界/溢出、有序ID和独立stream，再用 E33 四条校准root的32个真实hidden窗口做配对完整头计时。完整头（含copy、状态读取、回退）至少节时5%、root重采样95%下界为正、任一root不退化超过2%，才进入另8条旧工程root、4次重复的完整decode对照。任何正确性失败停止性能晋升；低收益/负结果如实保留，不基于测试结果重新选择容量或预算。

完整decode冻结E28 W8草稿、Q4草稿头、E17 NumPy预测器及E29费用，比较E33原筛选与E34。输出、提交logits/特征、最终live state、逐轮预算/接受轨迹必须相同；计时包括所有同步和循环，排除prefill、准备和检查。晋升门槛：decode至少+1%、root95%下界为正、四个重复均为正。只用常驻串行worker，源码/输入seal及实际执行源校验；不改默认服务。
