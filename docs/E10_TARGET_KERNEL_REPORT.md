# E10：target 专家重核的第一轮优化

2026-10-21。[方法](E10_TARGET_KERNEL_PLAN.md) · [完整脱敏数据](../results/e10/2026-10-21-target-expert.json)。状态 **PASS_EXACT_MICRO_NO_PROMOTED_OPTIMIZATION**。

**第一轮没有值得接入的提速：warp 数与寄存器预取深度的最佳筛选配置，在独立输入、缓存驱逐后的复核中仅快 0.08%（等权形状几何平均）。保留原核及 E8 默认执行路径，没有新增完整 decode 或 TensorFold 排名成绩。这个结果限制的是当前调参方向，不能解释成整个 target 已没有优化空间。**

## 实际做了什么

以 main `9727154`、E9 时间分布为起点，检查原 TensorFold NVFP4 专家核，使用 checkpoint 第 0 层真实的全部 512 个专家权重。仅改变每 block 的 warp 数（1/2/4/8）和寄存器预取深度（1/2），共 8 种配置，并保留原扩展作为基线。权重格式、BF16 激活、逐块 MMA/FMA 的累加顺序和输出精度均不变。

构建器核对外部 CUDA 源及共享头文件 SHA256，在独立目录生成变体，显式编译 `sm_121`。未修改上游安装和 E4–E9 冻结源，也未将权重、第三方源码或二进制引入仓库。重建的 4-warp/depth-2 是与原核相同几何和算术的控制。

输入为确定性生成的 BF16 张量，路由为手工指定的 distinct/shared/mixed 三类，包含每 token 的共享专家跳过槽。这不是实际整模激活或真实 router 输出分布。筛选覆盖 1/3/4/6/8 行生产窗口和 17 行压力条件；后者检查超过 16 个成员时的分组、第二组 MMA 行及 BF16 down 输出。其余窗口使用实际 decode 的 FP32 down 输出，包含带行间距输入。

每种变体检查 gate/up 激活、down 输出与原扩展精确一致，检查全部输出有限、首尾保护行和被跳过共享槽保持不变。共 **18×9 + 12×3 = 198 组精确变体检查**通过。此处包括原扩展自身作为控制，不是 198 次完整模型 oracle。

## 计时与独立复核

每个形状、缓存条件、变体有 6 轮，轮内变体顺序确定性打乱，每轮测 5 次 gate/up + down CUDA-event 区间并取中位数。包括 host 发射可能造成的两个 kernel 间隔；不是两个 kernel 各自的硬件累计时长。缓存条件分别为同一层反复复用，以及每对 kernel 前遍历读写 128 MiB 缓冲。后者是缓存扰动，不能证明所有缓存行都被逐出。

筛选阶段 15 个计时形状，共 **8,100 个 event 区间**；独立进程更换全部输入/路由种子，冻结 shortlist 为 2-warp/depth-1，另保留原扩展和重建控制，复核 12 个形状，共 **2,160 个 event 区间**。17 行仅用于正确性，不计入性能汇总。

下表速度因子均为“原扩展耗时 / 候选耗时”；各形状等权几何平均不是生产工作负载权重。

| 条件 | 筛选 2-warp/depth-1 | 独立复核 2-warp/depth-1 | 独立复核重建控制 |
| --- | ---: | ---: | ---: |
| 同层缓存复用 | 1.00473×（+0.47%） | 1.00532×（+0.53%） | 1.00019× |
| 每次 128 MiB 缓存扰动 | 1.00993×（+0.99%） | **1.00076×（+0.08%）** | 0.99766× |

按每个形状的中位数求和，独立复核缓存扰动条件下，候选因子为 **1.00227×（+0.23%）**，重建控制为 0.99936×。同层复用条件的候选因子为 1.00327×。这些口径均未显示值得增加运行时分派复杂度的收益，没有进一步运行完整权重生成 A/B。

筛选中某个形状的事后最佳配置曾显示约 8% 局部收益，但不同形状赢家不一致，且从多个候选中选最大值有选择偏差。不能把它当成专家核统一提速，更不能直接外推 decode。

## 还能有多大空间

E9 正常未采样数据中，整个 target 验证占 decode 约 83.81%。假定工作量、预算宽度及其余阶段不变，Amdahl 条件估算为：

| 整个 target 验证的速度因子 | 整段 decode 的条件速度因子 |
| --- | ---: |
| 1.20× | 1.162×（约 +16%） |
| 1.50× | 1.388×（约 +39%） |
| 2.00× | 1.721×（约 +72%） |

**这是条件推算，不是目前可实现幅度的预测。** 83.81% 包括主机调用、发射和同步；单个专家核只覆盖其中一部分。E9 专家家族的 36.05% 又是“累计 GPU kernel 时间”口径，不能与 83.81% 直接相乘或混作 decode 占比。动态预算还可能随成本变化而改变。

从保留的三份 E9 时间线提取的真实启动几何中，gate/up 每线程分配 128 个寄存器、down 为 96，均无记录到的 local memory；典型启动分别为 192/240 个 block，每 block 128 线程。这说明寄存器与启动形状值得检查，但分配量不等于实际 occupancy，零 local memory 也不能证明内存访问已最优。

尝试 Nsight Compute 2026.2.1 的 SpeedOfLight、Occupancy、MemoryWorkloadAnalysis，驱动返回 **ERR_NVGPUCTRPERM**，未取得带宽/SM 硬件计数器，没有更改系统权限。不能宣称已证明带宽瓶颈、满带宽，或给出可靠的带宽余量上限。

当前判断：**简单 launch/staging 调参的空间很小；减少实际读取、解码和数据搬运的结构优化仍值得研究，但尚无足够证据给整个 target 一个可信的预期提升百分比。** 下一批直接检查 qmmf 量化/共享投影与 BF16 大矩阵乘，并结合实际调用形状、读取字节数、布局和 kernel 时间寻找候选。涉及算术变化的方案需要单独设立数值及整模生成门槛，不能沿用本轮精确相等结论。

## 复现与证据边界

- 构建：`e10_build_experts.py --root <isolated-root> --external <pinned-tensorfold-root>`，依赖原 E1/E2 已准备的外部环境；`e10_expert_bindings.cpp` 放在独立 root。构建器固定 `sm_121`，不下载依赖或权重。
- 筛选：`e10_expert_probe.py --root <isolated-root>`；独立复核添加 `--holdout`。需要相邻 E2 的完整第 0 层提取文件与原扩展。
- 本轮筛选执行源固定在 `ffb04b8`，后续仅为 profile/holdout 分离输出文件名和加入独立种子复核；两轮 runner SHA256 和变体二进制 SHA256 均在数据中保留。`e10_export.py` 验证执行源及计时完整性，读取原始计时、E9 数据和错误日志生成公开记录。
- 初次继承容器的多架构构建被中止，随后显式重建 SM121；中断日志保留。profile 模式最初覆盖了筛选原始文件名，完整筛选 JSON 已提前复制到本地，公开记录使用该完整副本；后续脚本分开保存筛选、复核和 profile 准备信息。
- 仅两次独立微基准进程、一层真实权重和合成输入；没有新的完整生成、接受率、TTFT、模型质量或原生引擎排名结论。硬件计数器尝试单独运行，不混入正式 event 计时。OOM/OOM-kill 实查为 0，GPU 实验进程已退出。
