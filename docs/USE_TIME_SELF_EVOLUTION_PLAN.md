# 提议：日常使用中的无损自我进化

状态：**PROPOSED，EV0–EV6 尚未执行，本方案没有新的 GPU 结果。** 下文引用的 E33 是已完成的独立工程实验，不是 RSI 已运行或自动晋升的证据。实际排期时按阶段分配 E 编号；每个阶段执行前冻结输入、阈值和分析方法。所有提议的状态汇总在 [EXPERIMENTS.md](EXPERIMENTS.md#proposals-without-results-yet)。

## 要回答的问题

**主张：** 推理 infra 的自我进化可以做到对输出可证明安全、在统计上可靠。前提是一个逐位精确的无损引擎：每个候选改动都能在使用者真实记录上做精确的反事实回放，只有在时间上留出的新数据中证明有收益才晋升。

草稿器、验证宽度控制器和草稿来源选择属于由目标验证兜底的 A 类表面；前缀状态缓存属于 B 类，必须另过逐位一致性门槛。在已验证的 greedy 数值路径下，输出轨迹与这些策略无关；补齐候选可能访问的每个位置的草稿和特征后，可以沿同一轨迹精确计算候选的 token 产出。耗时仍由成本模型预测，不能从输出一致性直接推出。这两点是 harness 自我进化不具备的。

| 编号 | 问题 | 对应阶段 |
| --- | --- | --- |
| RQ1 | 整套投机栈的进化能否做到零输出变化 | 全部阶段，EV4 汇总 |
| RQ2 | 精确回放能否准确预测线上收益，近似回放会差多少 | EV0 |
| RQ3 | 有防护的进化与无防护的进化相比，错误晋升和性能回退差多少 | EV2 |
| RQ4 | 按证据触发的持续进化，能否胜过固定配置和一次性调优 | EV2、EV4 |
| RQ5 | 各个可进化部件分别贡献多少 | EV3、EV6 |
| RQ6 | 让进化器根据自己的历史记录进化，能否减少无效触发 | EV5 |

## E33 补充：历史复现与当前冻结基线

本节依据主线提交 `2cb909b2abc902912033334d107e6cf56e795de9` 的 [E33 报告](E33_EXACT_HEAD_SCREEN_REPORT.md)、[线上对照方案](E33_ONLINE_PLAN.md)和[脱敏证据](../results/e33/2026-10-23-exact-head-screen.json)。E33 是人工设计、冻结后验证的优化；它提供当前执行路径和记录格式，尚未证明使用期进化有效。

- **已有结果：** 8 条已用 E28 工程 root、每组 4 次重复，共 64 次正式计时。原完整头 46.9088 → 筛选头 48.5063 token/s，+3.4055%，root bootstrap 95% 区间 +2.3853%～+4.1211%，四次重复均为正。两组各产出 8,588 个计时 token、验证 12,748 行，预算、接受和提交轨迹一致；token、提交 logits、DFlash 特征和最终 live state 检查通过。
- **机制与代价：** INT8 辅助头粗筛、定向 FP64 保守误差界、原 BF16 子集精算；不满足条件则回退原完整头。原 BF16 权重和算术保留，另加 640,665,600 bytes 辅助 payload。正常生成的辅助副本准备约 762.395 ms，Graph/JIT 等准备也在稳态 decode 计时外。完整头组件节时 36.24% 不等于 decode 收益；不得与其他实验的百分比相加。
- **适用边界：** greedy、单请求、容量 2048 的既有工程输入；自然回退 0/2,596 轮，候选并集 1～116。零自然回退不是新流量永不回退的保证。未验证随机采样、多请求 batch、4K+ 上下文或新的真实流量，未切换默认执行器/SSE，也不是独立官方模型数值等价证明。

| 基线标识 | 冻结配置 | 在本计划中的用途 |
| --- | --- | --- |
| H16 | E16 原有五种模式、模型、草稿器、成本与数值路径 | EV0 历史跨策略回放；EV1–EV2 历史数据方法验证，不代表当前最优基线 |
| B33 | E28 W8 草稿 MLP＋Q4 草稿头、E17 NumPy 线性预测、冻结 E29 W8 费用、E33 融合筛选头和私有 Graph | EV0 当前路径检查；当前栈 EV2–EV4 的固定配置对照。精确沿用 E33 费用，先复现，再另立成本更新实验 |
| B33-full | 与 B33 相同，但使用 E33 的原完整 BF16 头 Graph | 数值、回退与成本诊断对照，不能单独作为 RSI 收益的主要基线 |

执行前须为 B33 冻结代码/二进制、target/draft 权重与量化 payload、预测器、费用、Graph 配置及数值范围/cap/回退规则的哈希清单；上述主线提交只是来源锚点，不能替代运行时输入 seal。B33 实际宽度选择沿用 [`choose_rows`](../spark_infer_q/confidence_head.py)，与 E33 实测一致；历史 H16 的 MTPVarlen 绑定另行固定，不能为统一接口而悄然替换。进化组和固定组共享相同执行路径，RSI 收益只相对于同一 B33 固定组计算，不能把 E33 相对完整头的 +3.4055% 记作进化收益。

**筛选头暂不列为可进化表面。** 它位于目标决策路径，不能归为“由目标验证兜底、只影响速度”的 A 类。其正确性依赖当前硬件、误差模型、数值范围、原 BF16 精算和回退契约；与可信核心一起冻结。将来若调整辅助格式、误差界、候选 cap、子集核或回退条件，须另立 B 类实验，先过数值契约、逐位 oracle 和完整生成门槛，再重新验证 EV0；EV0–EV4 不允许编辑器修改它。

E33 逐轮日志已有宽度、接受/提交、分阶段耗时、候选并集和回退字段，但只覆盖实际访问的位置。新宽度策略会改变步边界；须在 B33 自己的串行轨迹上补齐所需位置的草稿、特征和各宽度产出。E16/E17 的稀疏位置或 BF16 草稿标签不能直接充当 W8 草稿的完整反事实数据。筛选成本还受 hidden、宽度、候选并集和回退影响，原始 E29 费用不能被当作 E33 真实耗时；用独立校准数据建立 B33 的评估成本模型，并与供决策使用的冻结 E29 费用分开记录。改变步边界后，未记录的筛选行为须通过 GPU 补测，不能把同位置日志外推为精确计时。

## 与已有工作的边界

| 工作 | 已经做到 | 本计划多出的部分 |
| --- | --- | --- |
| [Autopoiesis](https://arxiv.org/html/2604.07144) | 服务过程中由大模型持续改写服务策略 | 输出安全的架构、精确回放评估、按证据晋升；EV2 正面比较无防护进化 |
| [Not-a-Bandit](https://arxiv.org/pdf/2510.20064) | 用已验证轨迹无偏估计其他草稿器的接受长度 | 回放整套策略，包括步边界移动、草稿来源、宽度和计时 |
| [TIDE](https://arxiv.org/html/2602.05145)、OSD、EvoSpec | 服务中在线更新草稿器 | 草稿器只是可进化部件之一，且晋升需过时间留出检验 |
| [ADRS](https://arxiv.org/pdf/2510.06189)、AlphaEvolve | 离线在模拟器上进化系统算法 | 在使用期、用真实记录进化，评估器是精确回放而不是近似模拟 |
| [Harness²](https://www.kdnuggets.com/google-open-sources-harness-self-improving-ai-agents-without-retraining)、[HarnessPro](https://arxiv.org/html/2610.26770) | 进化 agent 的外壳，靠运行对比或 AI 生成测试判断好坏 | 进化对象是推理栈，有逐位 oracle 和真实计时作为客观裁判 |
| [Marconi](https://proceedings.mlsys.org/paper_files/paper/2025/hash/7c180af017258d239bac6248d1eb26ac-Abstract-Conference.html) | 混合模型前缀缓存的通用准入和淘汰 | 按使用者进化快照策略，并要求复用与重算逐位一致 |

[Re-feeding Is Not Replaying](https://arxiv.org/pdf/2606.15621) 报告：普通推理引擎重放记录并不能复现当时的状态，只有在批次无关的内核下才精确。本计划依赖本仓库已经验证的逐位一致路径（E8 起的行数无关 decode 算术），这是精确回放成立的前提，EV0 要先证明它。

执行前须通读 Autopoiesis 和 Not-a-Bandit 全文，确认它们没有覆盖上表右列。

## 可进化表面与安全类别

安全类别：

- **A 类：** 正确性由目标模型验证保证，只评估速度。
- **B 类：** 数值必须逐位不变，先过逐位 oracle 再评估速度。
- **C 类：** 会改变输出，本计划不进化。

| 编号 | 部件 | 类别 | 评估方式 | 依赖 | 起始阶段 |
| --- | --- | --- | --- | --- | --- |
| S1 | 验证宽度预测器：重新标定、重训预测头 | A | 精确回放 | 草稿器输出分布 | EV1 |
| S2 | 草稿来源选择：DFlash、整轮跳过草稿，以及将来的记忆表和复制草稿 | A | 精确回放 | S1 | EV3 |
| S3 | 草稿器 backbone 精度：按层组选 BF16、FP8 或 INT8 | A | 夜间 GPU 重算草稿后回放 | S1、S2 | EV3 |
| S4 | 成本曲线 | A | 计时干净时滑动更新 | 无 | EV2 |
| S5 | 前缀状态快照：保存位置、保留与淘汰 | B | 请求流模拟，复用须与重算逐位一致 | 执行器支持跨请求状态复用 | EV6 |
| — | 目标模型量化、近似验证、思考预算、采样参数 | C | 不纳入 | — | — |

一个部件晋升后，依赖它的部件自动进入复查。例如 S3 改变草稿器精度后，S1 必须在新草稿上重新验证。

开启随机采样后，A 类的接受率估计必须遵守 MTPVarlen 的滞后约束，或另行证明不改变采样分布。本计划所有阶段只覆盖 greedy。

## 阶段与门槛

以下阈值都是初始建议，执行前冻结。E12 同动作计时波动中位数为 3.5%；E33 在配对、平衡顺序和重复计时下确认了约 3.41% 的 decode 收益。因此不以单次计时噪声直接判定收益，沿用配对比较、按 root 分组的区间和逐重复敏感性检查。

### EV0：回放保真度（地基）

- **历史复现 H16：** 用 E16 在线对照的逐轮日志（5 种模式，各 60 次计时，20 个任务）。在 Spark 上补算这 20 个任务串行轨迹每个位置的 DFlash 草稿，每个位置约 10 毫秒。然后只用某一种模式的日志，回放预测其余 4 种模式的逐轮决策、token 数和耗时，与实测比较。另外计算 E15/E16 离线评估所用的均匀前缀估计，与实测比较。
- **当前路径 B33：** 先用 E33 的 original/screened 日志复查相同步边界下的产出、数值检查与两种头路径的成本预测；两组原本决策一致，不能据此宣称跨宽度回放通过。随后冻结独立校准数据、补齐 B33 逐位置草稿/特征和宽度/筛选计时，并在预先冻结的宽度策略间补做配对实测，检验步边界改变后的回放。已有 E33 结果不替代这次验证。
- **指标：** 逐轮决策与 token 数的一致率；耗时预测误差；5 种历史模式的快慢排序是否保持；均匀前缀估计的误差；B33 跨宽度预测误差、候选并集和回退成本。
- **门槛：** 对每个被回放策略，逐轮决策、提交产出和拼接后的 token 序列与该策略实测完全一致；跨模式的耗时预测，按任务中位相对误差不超过 3%，排序保持。H16 与 B33 分别报告；H16 通过不能替代 B33 的当前栈门槛。
- **停止条件：** 达不到门槛且无法定位原因，就停止整个计划，因为核心主张不成立。
- **资源：** H16 需 GPU 补算草稿；B33 还需 GPU 补测各宽度筛选/验证成本与配对 decode。回放与统计在 CPU 上完成，不改可信执行路径。

### EV1：数据充分性与漂移检测

- **做法：** 按 10%、25%、50%、100% 的训练提示组，分别重训 E16 的 F1 预测头，画出数据量和回放收益的曲线。按任务族排序，人为制造漂移，测校准漂移统计量的检出延迟和误报率。
- **产出：** 冻结给 EV2 用的触发阈值：最少请求组数、各深度最少标签数、预计收益下限。
- **门槛：** 能定出一组阈值，使模拟漂移在合理延迟内被检出，且无漂移时误报率不超过 5%。
- **资源：** H16 数据分析只用 CPU；B33 曲线须使用 EV0 补齐、与当前 W8 草稿一致的特征和标签，再在 CPU 上拟合。

### EV2：模拟多天进化，单一部件

- **做法：** 在 U1 和 U2 上按天推进，只进化 S1 和 S4。先在 H16 历史数据上验证方法，再在通过 EV0 的 B33 完整数据上独立重复；不跨栈混用标签、费用或汇总收益。每一轮各设五个对照组：
  1. 固定配置（历史轮为 H16 的 E16 F1；当前栈轮为 B33）；
  2. 一次性调优，在第 k 天用同样多的数据调一次；
  3. 本方案，按证据分级触发；
  4. 无防护进化，只要最近窗口的点估计更好就替换，不做时间留出和最小效应检验；
  5. 定时进化，每天都重训。
- **指标：** 累计回放耗时；第二天速度；晋升次数；错误晋升次数，即晋升后在之后两天回放更慢的次数；相对于每天事后最优配置的差距。
- **门槛：** 本方案的累计耗时优于固定配置，区间下限大于零；不劣于定时进化，且更新次数更少。
- **如实报告：** 如果无防护进化并没有更多错误晋升，防护机制的价值就要降级表述。
- **资源：** 已完成各自数据补全和成本校准后，模拟与拟合只用 CPU。

### EV3：扩展可进化部件

- **做法：** 加入 S2 和 S3。S2 先在 DFlash 和整轮跳过草稿之间选择，[E18](E18_PREDRAFT_COMPUTE_REPORT.md) 已指出低收益位置整轮跳过值得验证；记忆表和复制草稿器通过各自门槛后再并入。S3 在夜间用 GPU 按候选精度重算草稿。启用依赖复查。
- **指标：** 每个部件单独以及组合后的回放收益；依赖复查触发的次数和结果。
- **门槛：** 每个部件晋升的配置在时间留出数据上收益至少 2%，区间下限大于零，逐位 oracle 抽查通过。
- **资源：** S3 需要夜间 GPU；不改执行器的验证路径。

### EV4：在线验证

- **做法：** 冻结一段 U2 使用流，可选再加 U3，共 10 到 14 个压缩的"天"。每天的请求通过真实执行器、用当天已晋升的配置运行；两天之间运行一次进化任务。同一使用流上配对运行固定 B33 配置组，进化组也保留相同 E33 筛选/回退路径。H16 只作历史诊断，不作为当前栈收益的主要基线。
- **指标：** 逐天的 decode token/s；全部正式输出与固定 B33 组和原完整 BF16 串行参考的一致性；提交 logits/特征/live state 的逐位 oracle 抽查；预计收益与实际收益之比；回滚次数；筛选候选数、回退率、辅助内存及准备成本。另报补算/训练/搜索/验证成本和扣除这些成本后的净节时，不将稳态 decode 提升直接称为使用期总收益。
- **门槛：** 最后三天相对固定 B33 组的速度提升区间下限大于零；输出差异为零，数值 oracle 检查通过；预计与实际收益之比落在 0.7 到 1.3。对新使用流须保留 E33 的原完整头回退；若出现回退或候选分布变化，计入全部成本并复查预测校准，不把它单独视为输出错误。
- **资源：** 需要执行器支持按配置版本切换策略，以及记录器；不改可信核心。

### EV5：进化器自身的进化

- **做法：** 用 EV4 的进化日志更新进化器的参数：触发阈值、各类候选的预算分配、收益估计的校准。在一段全新的使用流上，比较原始进化器和更新后的进化器。
- **指标：** 无效触发率，即触发了但没有晋升的比例；获得首次收益所需的天数；预计收益的校准误差。
- **门槛：** 三项中至少两项改善，区间下限大于零；否则保留原始进化器并报告。

### EV6：前缀状态快照（并行的工程线）

- **前提：** 执行器支持跨请求复用 GDN 和 QSA 状态，复用结果与从头重算逐位一致。4K 上下文的一个快照约 0.35 GB。
- **做法：** 在 U4 上比较四种策略：不缓存、最近最少使用、Marconi 式通用策略、按使用者进化的策略。
- **指标：** 首 token 延迟、token 命中率、快照占用内存。当前逐位精确的 prompt 路径约 109 token/s，2000 token 上下文重算一次约 18 秒，所以这一项对 agent 场景的体感影响可能最大。
- **门槛：** 复用全部通过逐位 oracle；进化策略的首 token 延迟优于 Marconi 式通用策略，区间下限大于零。

## 风险

- **回放保真度不够。** 若 EV0 失败，整个计划停止。
- **个人化没有学习曲线。** 若 EV2 的进化组与固定配置持平，说明在当前任务上个人化收益有限，如实报告；重心转向更依赖使用模式的 S5。
- **每天的数据太少。** 一个人一天可能只有几万到几十万 token，触发会很少。可以把"天"合并成"周"，触发频率本身也是结果。
- **计时噪声。** 沿用平衡顺序和夜间计时；计时不干净的时段降权或丢弃。
- **编辑器写出的策略代码有性能回退。** 逐位 oracle 拦不住变慢，所以时间留出检验和回滚不能省。
- **领域变化快。** Harness² 和 Autopoiesis 都是今年的工作，越早拿出 EV0 到 EV2 的结果越好。

## 执行顺序

1. EV0 先做 H16 历史复现，再完成 B33 当前路径数据补全、成本校准和跨宽度实测门槛；EV1、EV2 在各自数据与冻结栈内推进，模拟/拟合主要在 CPU 上完成。E33 的既有 +3.4055% 不计入 RSI 增量。
2. EV3 需要夜间 GPU。
3. EV4 需要执行器支持配置版本切换和使用记录器。
4. EV5 依赖 EV4 的进化日志。
5. EV6 是独立的工程线，与 [Kaifra 路线图](KAIFRA_IMPLEMENTATION_ROADMAP.md) 的跨请求状态管理共用前提，可以和前面并行推进。
