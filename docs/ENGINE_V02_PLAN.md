# 统一服务 v0.2：四请求与 32K 上下文

本阶段固定验证范围：同一常驻模型，最多四个运行请求，每请求 32768
tokens（输入与输出合计），target KV 保持 BF16。排队请求另计。

复用 E54 的私有请求 Graph、滚动 DFlash 历史、请求私有投影缓存和
原生 Scheduler。长请求共享串行 GPU 工作区；四个活跃状态不等于四路
GPU batch。原有双请求短上下文 GPU batch 路径继续可选。

验收前不提升为已验证能力：

1. CPU：容量边界、四槽所有权、同步执行器接入异步 HTTP owner、取消与队列。
2. GPU：短提示的 eager/Graph logits、五层特征、状态与部分提交核对；
   四份接近 32K 的真实输入同时驻留，各自与隔离执行比较 token、状态、
   草稿预测率和动态验证宽度。混合中英文及代码，不能只分配空缓存。
3. HTTP：四请求 streaming/nonstreaming、完整请求延迟、首内容时间、
   取消及幸存者、请求复用、超容量拒绝、排队与恢复。
4. 内存：保留 88 GiB 进程上限和 8 GiB 主机余量；逐槽实际测量，
   加入草稿特征/投影缓存及暂存空间后再批准额外槽；记录峰值与清理。

只在切换到可验证的新服务时重新加载一次权重；测试重用同一个 session。
不运行固定草稿对照，不下载权重，不修改另一工作区的未提交四路实现。
超出 32K、八并发、压缩 KV 精度、多路长上下文 GPU batch 均不在本阶段声明范围。
