## 波动与收益边界

NumPy冻结费用版相对原Python的三轮整体变化为+1.1966%、+0.2973%、+0.3114%。在prompt重采样中再成对重采样重复轮次，其95%敏感性区间为−0.1586%～+1.3690%，跨零。因此记录小幅正信号，不宣称稳定的0.60%普遍收益。

实时费用版对原Python三轮为+0.5096%、−0.0846%、−0.2195%，对NumPy冻结费用版为−0.6789%、−0.3808%、−0.5292%。进一步重采样重复的区间分别−0.7887%～+0.9523%、−1.1598%～+0.1397%，也跨零。不把较窄的prompt区间解释为已确定的普遍退化。

本轮是12个受控root，分层每类只有2～4条，不能外推一般用户流量。实时修正对冻结NumPy的两条长输入合计+0.3502%，多轮−1.0744%；只作描述，不能挑正子集当主结论。没有固定草稿或原生TensorFold对照，不衡量整个动态预算的总收益。

## 为什么还没有明显提速

| 同样10,419个decode token | 验证轮数 | 每轮输出token | 完整轮均耗时 |
| --- | ---: | ---: | ---: |
| 原Python线性 | 3,498 | 2.9786 | 68.6511 ms |
| NumPy线性，冻结费用 | 3,498 | 2.9786 | 68.2408 ms |
| NumPy线性，实时修正 | 3,502 | 2.9752 | 68.5258 ms |

纯执行优化的两个方案在全部计时中的context/验证宽度/输出/接受标签轨迹完全一致。CPU预检中完整predict从0.051960降至0.008917 ms，约5.83倍；但它只占约68 ms完整轮的很小部分。实测总耗时差1,435.43 ms，其中target验证计时差1,257.73 ms，约87.6%。这不能全归因于小头提速，亦没有独立隔离GPU频率、缓存等机制；CPU微基准不能作为完整decode加速倍数。

实时修正多4轮（+0.1144%），没有减少验证工作。该组耗时分布：target验证82.4241%、草稿/特征/预测/调度15.9469%、commit1.3994%、其余循环0.2297%。这是观测构成，不能视作各组件可独立移除的上界。

本轮不同轨迹上的验证＋commit费用平均绝对预测误差分别为原Python2.1727 ms、冻结NumPy2.2852 ms、实时修正2.0862 ms。这些轨迹与计时并不相同，不能作为匹配反事实的成本准确率因果对照；尤其误差较小没有转成实际decode收益。只使用过去已完成步骤的因果预测已从全部trace独立重放核对，未用当前验证结果选当前预算，也未看test改参数。
