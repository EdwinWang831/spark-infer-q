## 128K 的实际时间分布

英文和中文各一条真实 131008-token 输入，分别在位置 1024、65536、
129024 取得 CUPTI trace，并在相邻块独立取得阶段 event 诊断。
两条完整输入及后续 64-token 控制的输出、状态和特征都与封存控制一致。
六份 trace 仅用于诊断。

下面的范围覆盖这两条输入，单位为每个 1024 行块的累计 kernel 毫秒。

| 家族 | 开头 | 中段 | 末段 |

| 路由专家 | 190.6–197.4 | 200.4–205.7 | 197.8–206.0 |
| 量化投影 | 104.1–108.3 | 103.9–107.4 | 106.7–114.1 |
| BF16 投影 | 54.5–56.1 | 53.6–54.3 | 54.2–54.6 |

| 其他 | 118.9–120.1 | 116.9–118.0 | 117.6–118.5 |

QSA 的成本随上下文增长。专家和两类投影合计仍占约 48%–60% 的
累计 kernel 时间。root wall 中设备活动区间并集以外的部分约为
29–34 ms，约 3.6%–5.4%，包含提交、同步与剖析扰动。
该统计提供 Graph 覆盖的时间边界，带宽与执行单元利用率需要硬件计数。

旧 E37 分类器将 E44 tile 与若干 QSA 名称放入 other。本轮导出时按
已核对的实际 kernel 名称分类，原始 trace、原统计和 SHA256 均保留。
新增 classifier 参数的默认行为经回归测试核对。

## QSA 实现与筛选

打分沿用 TensorFold 的逐 head FP32 累加、ReLU 和维度归约。
本仓库的 Gluon 实现用两个相邻查询共享池化索引 tile，并显式指定
每线程八个相邻元素、沿维度十六个 lane 的归约布局。较长多行输入
调用外部 TensorFold 确定性 radix selector，按较小 block ID 处理同分。
来源和 MIT 声明见[第三方说明](../THIRD_PARTY_NOTICES.md)。

在 8192、32768、65536、129024 四个位置，每臂六轮 AB/BA、每次十次
QSA 调用的组件筛选中，总 GPU event 时间减少 **23.0487%**。
五组边界检查逐个核对完整 score 存储、选择 ID、长度与 sparse 标记。
另外八组检查覆盖随机分数和全同分选择。该组件结果的放大系数由完整
cohort 配对实际测定，最终请求耗时减少 1.9865%。

保留的其他候选如下。

| 候选 | 数值结果 | 成本结果与处置 |
| --- | --- | --- |
| HC 回写与归一化融合 | 三条完整前缀的 logits/features/state 一致 | 两条 1024-token 前缀 prompt 耗时减少 1.4863%，止于筛选 |
| 自动三维广播打分 | 17 行、位置 4095 的 score 逐位检查失败 | 弃用，失败作业与源封存 |
| 二维逐查询共享读取 | 五组组件检查一致 | QSA 组件耗时减少约 2.06%，止于筛选 |
| 显式布局双查询 | 五组组件检查一致 | 组件耗时减少约 11.27%，随后组合 radix 选择 |
| 显式布局四查询 | 五组组件检查一致 | 组件耗时减少约 7.93%，采用双查询进入完整配对 |
| 寄存器驻留 radix | 八组检查含三组全同分，结果一致 | QSA 组件耗时为对照的 2.898 倍，止于筛选 |

寄存器候选的硬件慢因尚未测定。本轮依据实测成本作处置。

## 数值、内存与恢复

- 1024、1025、4097、32769-token 前缀的完整末行 logits、全部五层
  拼接特征和有效状态一致。41 个 prefill 块及其保留后缀逐块核对 SHA256。
- 每个前缀随后执行 width 1–8 的 Graph 验证，奇数完整、偶数半提交，
  共 32 个窗口通过。四轮正式请求均匹配冻结逐 token 控制，动态宽度、
  接受和概率轨迹一致。
- 正式样本增加的 draft capture 为零，head kernel 集合稳定，Graph/head
  fallback 为零。长请求 GPU 执行采用共享串行工作区。
- 完整研究 peak allocated **86.979 GiB**、peak reserved **87.955 GiB**，
  最低采样主机可用内存 **17.220 GiB**，通过 88 GiB、8 GiB 和 1 GiB
  暂存预算条件。
- 同一进程、同一 target/draft 对象，`load_count=1`。v0.4.1 由封存
  源复制到新的唯一快照后恢复，81 个服务 Python 文件与提交
  `c3f0103496f65ec24a2f8973cc28802a885c5b73` 的内容一致。
- 恢复后重放封存 HTTP 用例，221 输入、64 输出，耗时 **1.872 秒**，
  文本和用量一致，服务返回空闲。此项是短请求恢复检查。本轮候选
  因晋升门槛未通过，未执行 HTTP 四长请求配对。
