# E32：量化投影紧凑 staging，数值正确但性能退化

2026-10-23 UTC，`REJECT_E32_COMPACT_PERFORMANCE`。本轮确实找到并去掉了无效输入行的共享内存填充，但真实投影回放约慢 1%，停止候选，不做完整 decode 晋升。[事前方案](E32_COMPACT_STAGING_PLAN.md) · [完整脱敏计时](../results/e32/2026-10-23-compact-staging.json)。原有 W8 草稿、线性预算和 target Graph 不变。

## 找到了什么可以减少的工作

MXFP8 投影的 qmmf 对 1～8 行输入使用固定 BM16。原核每 stage 为输入保留 16×128=2048 bytes，除了有效行，还对其余行执行 `cp.async` 零填充。候选仅存有效输入行，`ldmatrix` 对无效 MMA 行复用第0行的有效地址；最终仍只写有效输出行。

BM16、BN64、4 warp、4 stage、split-K、cluster 归并和全部有效行的 MMA/FP32 FMA 顺序保持原样。同一次构建包括原 CROWS16 逻辑控制和 CROWS1～8 紧凑候选；没有重扫 E10/E11 的几何或归并参数，没有改权重/激活精度或复制权重。

| 实际行数 | 原共享内存/CTA | 紧凑版本 | 减少 |
| --- | ---: | ---: | ---: |
| 1 | 25,088 B | 17,408 B | 30.61% |
| 2 | 25,088 B | 17,920 B | 28.57% |
| 4 | 25,088 B | 18,944 B | 24.49% |
| 8 | 25,088 B | 20,992 B | 16.33% |

这是实际声明/使用的动态共享内存布局变化，**不代表整机内存减少相同比例**。它消除了无效行填零，却没有减少全局权重字节、有效输入字节或 MMA 次数。没有硬件 counters，不能由此宣称 occupancy 提高或 DRAM 已饱和。

## 正确性与采集修正

在同一常驻 worker 上，四类真实矩阵的 224 组数值筛查覆盖 1～8 行、连续/带 stride 输入、尾部列以及可整除 K 的 SK1/2/4/8；同次编译的原逻辑控制和候选都与现有 resident 扩展逐位一致，边界哨兵保持原值。另一个 CUDA stream 的检查也通过。

真实输入来自 E30 四条已用校准 root，每条前两轮、第0/23/47层的块输入/输出及 shared gate/up、down：共96份输入。实际宽度2/4/5/6/8；五种 `(N,K,SK)` 为 `(1280,2560,4)`、`(2560,640,1)`、`(2560,6144,8)`、`(13952,2560,1)`、`(16480,2560,1)`。全部输出与真实前向逐位一致。8次诊断前向的完整 logits、DFlash特征和提交live state也与冻结Graph一致；这是采集路径验证，不是全模型换核后的生成验证。

第一版采集器仅取得72份真实输入：复制模块并重绑函数 globals 后，`MoE4.shared_act` 类方法仍引用原模块，绕过了 shared gate/up 采样钩子。末尾的96例完整性断言正确地让作业失败；此前224组筛查、72份输出与8次诊断检查没有数值失败。旧源码、seal、RUNNING中间报告和作业FAIL记录全部保留，未覆盖或冒充成功。修正版只在浅拷贝的专家对象上重绑该方法，补齐96例；候选内核、二进制、输入清单与事前性能门槛均未改变。

新增两个CPU回归测试检查：模块内部嵌套调用使用私有钩子而不改变原函数globals；类方法确实通过私有代理被观测，原类/对象的方法不被替换。采集修正不修改全局 dispatch。

## 真实性能：省 shared memory 没有兑现为提速

每份输入将原核与候选分别捕获为单投影 CUDA Graph。热复用每个event区间10次replay，128MiB缓存扰动每区间1次；各6次配对交替。共2,304个event区间、12,672次计时投影。预热、capture、clone、校验和缓存扰动均在计时外；独立回放的缓存分布不能当作整模型缓存分布。

| 条件 | 原核的96例中位数之和 | 紧凑版本 | 速度变化 | root bootstrap 95%区间 |
| --- | ---: | ---: | ---: | ---: |
| 热复用 | 6.018554 ms | 6.083006 ms | −1.060% | −1.605%～−0.623% |
| 128MiB缓存扰动 | 9.837152 ms | 9.928640 ms | −0.921% | −1.369%～−0.370% |

这批输入中两个区间均为负，且未达到至少10%投影节时门槛，拒绝晋升。不是“尚待证实的正收益”，也没有新增decode TPS。

按形状的缓存扰动后验拆分如下，不能用它改变已封存的主门槛：

| `(N,K,SK)` | 输入数 | 速度变化 |
| --- | ---: | ---: |
| `(1280,2560,4)` | 24 | −0.111% |
| `(2560,640,1)` | 24 | +2.567% |
| `(2560,6144,8)` | 24 | +0.044% |
| `(13952,2560,1)` | 16 | −1.997% |
| `(16480,2560,1)` | 8 | −1.490% |

shared down 的局部小收益没有形成整体正收益，不据此继续细分或追加参数扫描。地址别名改变了 shared 访问布局，可能带来额外代价；没有 counters 或隔离实验，不能把退化具体归因于 bank conflict、occupancy 或带宽。

## 结论与后续筛选原则

E31减少转换，E32减少无效共享内存填充，两者都没有减少占主要体积的权重读取或有效矩阵计算。本轮说明仅找到“可省操作”不够，下一候选应明确能少读多少全局权重或少算多少有效矩阵行，再做成本验证。

仓库已有、尚未执行的[精确 greedy 输出头筛选方案](EXACT_HEAD_SCREEN_PLAN.md)符合这个更大的改动方向：低位宽副本只负责排除不可能获胜的词，候选仍用原BF16头的相同算术精算，有非有限值、上界无效或候选过多时回退完整头。它有机会减少每轮完整读取约1.27GB BF16头的工作，区别于E30仅改变头布局。但真实候选数量、GPU误差界、筛选/精算成本和最终吞吐都尚未验证，不能作为本轮已取得的收益；也不改变target权重或随机采样路径。E30中头只占target kernel时间约10.5%，收益空间仍受该占比限制。
