# E17：针对实际预算损失的补训准备

2026-10-22，阶段目标是准备可审查的数据、损失与门槛，不先盲目扩大模型。沿用E16已冻结的F0/F1作为参考，不修改Target/DFlash主体、量化或缓存算术，不重载常驻模型。

## 已有数据仅作训练挖掘

`e17_prepare.py`只允许E16原train的300提示/18,567位置进入补训权重与难例池。旧calibration仅提供已冻结成本和参考吞吐；旧test/OOD已看过，后续只能作回归诊断，不能重新宣称独立新验证。

以冻结参考吞吐λ，定义动作效用 `emitted / λ - cost_ms`，错选宽度的训练信号是最佳可行动作效用减预测动作效用。这是Dinkelbach意义下的等效毫秒损失，**不是可直接回收的在线时间**，也不是逐位置最大token进展oracle。剩余输出容量统一约束动作。所有动作已经付出的草稿成本不得漏计。

基于train的p90等效损失，权重限制在1..4；正式拟合时在每个条件头的有效训练子集中归一化。保留未加权原始样本，不只训练难例。512位置复核池按英文205/中文205/混合102分配，每提示≤8、每语言内每任务族≤20%，不从test/校准/OOD挖掘训练样本。它是后续配对实测成本的优先池，不是独立评测集。

现有在线日志只有所选宽度的真实时间，其他宽度是反事实缺失，不能仅据这些日志把损失完整拆成“概率错误”和“成本错误”。下一步在train池的分散位置测同前缀各宽度，再决定补接受率头还是成本预测。当前成本偏差诊断不作为新的性能收益。

## 新来源与划分

准备引入OpenAssistant/oasst1的人工root提示，源固定到commit `fdf72ae0827c1cda404aff25b6603abec9e3399b`，Apache-2.0。仅文本，非权重；不使用assistant答案，不记录原始user_id。来源、message_id、源文件SHA及派生关系留档。原始源与文本在gitignored目录；公开文档保留许可证和归属。

目标600条：英文240、中文240、由其中120个root生成的中英混合派生变体。相同root和近重复文本必须同组同split；先固定新train/calibration/test，再看任何Target标签。建议总420/90/90，各split保持40/40/20；原生英文/中文题目分别来自对应语言，不以翻译代替全部英文题。源过滤、可用数量和实际容量预检以冻结清单为准。它是公开人工提示，不是本产品用户流量或美国用户代表样本。

新测试集保持封存，不用于挖难例或选择权重。先用train/新calibration选择普通与加权F0/F1，再打开新test；旧E16套件只回归。保持原始样本混合，限制上采样，避免全向困难样本偏移。拟合仍先用小头，不因现有结果直接增加MLP。

## 进入正式补训的门槛

1. 新源许可、文本清单SHA、root/近重复划分及实际token容量通过。
2. 配对成本复核能说明高损失位置；未测反事实不补成“真实成本”。
3. 普通/加权拟合的对照与超参数提前固定；新校准只选一次，独立测试语言收益和预测成本都报告。
4. 通过后再做包含全部开销的新提示在线对照。不把Brier改善、等效损失或旧测试上的收益直接当新TPS。

本阶段不自动重新采集600条、重训并替换现有模型；先交付准备与成本归因，避免在假成本标签上扩大训练。
