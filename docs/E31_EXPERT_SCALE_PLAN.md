# E31：专家核的成对 FP8 scale 解码

冻结 E28 INT8 草稿、E17 NumPy 线性预算、E29 W8 费用和完整 target Graph。复用同一常驻进程及权重，不修改旧封存源码或全局 dispatch。

单一候选将专家内核每对相邻 scale 的两次标量 FP8→FP16 转换改为一次 FP8x2→FP16x2 转换，再转换到 FP32。保留原 NVFP4 权重布局、BF16 激活、MMA、逐块 FP32 FMA 顺序、全局 scale、epilogue、4 warp 和双预取。意图是减少转换工作；是否编译为更少指令、是否更快均需验证，不预设瓶颈来自转换。

先在 GPU 穷举全部 65,536 对 FP8 字节，有限值及有符号零按位核对，NaN 位置核对。随后复用 E30 四条校准 root 的前两轮真实动态预算轨迹，在第 0、23、47 层保存真实输入及设备路由计划。诊断回放和计时位于正常 decode 之外，通过实例局部遍历取得数据，不替换全局函数。诊断完整前向的 logits、DFlash 特征与提交状态需与冻结 Graph 一致。

每例检查 gate/up BF16 输出和 down FP32 输出逐位一致，跳过的 shared slot 和边界哨兵保持原值。为原核和候选各捕获只含 gate/up 与 down 的两节点 CUDA Graph，用 Graph replay 交替计时，避免逐核 Python 发射间隔影响结果，覆盖热复用及 128 MiB 缓存扰动；每种情况 6 次配对，热复用每个区间 10 次专家 pair 调用，缓存扰动每个区间 1 次（避免区间内重新变热），计时外做检查。每例单独重放，故不把它称为整模型缓存分布。候选没有新增权重副本。

事前晋升门槛：全部数值与状态检查通过；缓存扰动下专家 pair 合计耗时至少降低 10%，按 root bootstrap 的速度收益 95% 下界为正，且没有单个 root 超过 2% 退化。未通过即结束本候选，不做几何扫描或长 decode。通过后才另外封存完整正常 Graph decode A/B，微基准不能当作实际吞吐收益。
