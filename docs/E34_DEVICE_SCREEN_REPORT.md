# E34：固定容量 GPU 候选压缩，完整头节时 3.78%，未过成本门槛

2026-10-23 UTC，`REJECT_E34_HEAD_COST`。相对 E33 已经融合并使用 Graph 的筛选头，新版把有序候选压缩、原 BF16 子集精算和 argmax 也纳入固定容量 Graph，完整头耗时减少 **3.7845%**。四条 root 都为正，但未达到[事前方案](E34_DEVICE_SCREEN_PLAN.md)规定的至少5%节时，因此停止本候选，不启动完整 decode 长测，不切换默认路径。没有新的 decode token/s 结论。[脱敏完整计时](../results/e34/2026-10-23-device-screen.json)。

## 改动与正确性边界

E33 的 backbone 和筛选近似/误差界阶段已经使用 Graph。本轮不是首次启用 Graph，也没有改变专家核、辅助量化、界、预算或接受规则。沿用逐输出通道 INT8 辅助头、定向 FP64 区间、cap2048，以及原 BF16 BK64/SK1 精算。辅助权重与 E33 基线共享，不重新加载 target/draft。

新增 GPU tile 计数、有序压缩和固定2048槽候选缓冲。精算核读取设备端真实候选数，跳过空 tile，尾部填负无穷；候选排序保持最小 token ID 的并列规则。主机通过一次3元素状态读取检查输入有效性、候选数和精算有限性，需要时仍回退原完整 BF16 头。没有宣称全异步或移除所有主机往返。

15项功能检查包括1～8行、全零并列、NaN、Inf、超出有限范围、强制cap回退及独立stream。5项压缩检查覆盖空集、tile边界、2049候选溢出、词表尾部和缓冲guard。对32个真实hidden窗口，完整argmax、候选ID顺序、候选BF16值、误差界和保留mask均与E33一致；候选值另与原完整BF16头逐位核对。自然候选并集4～20，无自然回退。

未运行新候选的完整生成/live-state对照，不把这些组件检查写作新的整模正确性或质量证明。只针对现有greedy路径，随机采样沿用原完整分布。

## 首轮失败与修正

`185-e34-device-head.json` 在独立stream检查时失败，未进入真实窗口计时。单独的 `186-e34-diagnose.json` 发现宽度复用后新版误触发 `nonfinite_exact`，默认stream也可复现；因此不是笼统归因于跨stream。原BF16回退使诊断输出仍正确，但该版本不能用于性能结论。

原因是新版在捕获前分配了 `ranks` 张量，Graph引用其设备地址，类却没有保留其存储生命周期；其他分配复用该内存后，有限性mask失效。修正版 `e34_device_head_v2.py` 显式持有每宽度的索引存储。原版本、源码seal、失败结果与诊断均保持不变；新版本以独立seal和新作业 `187-e34-device-head-v2.json` 重跑所有检查和正式组件计时。
