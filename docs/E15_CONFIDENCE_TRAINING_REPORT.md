## 模型

两种事前固定消融均训练完成：F0为25维连续分数及已知请求状态；F1增加七位置hidden的固定2560→16随机投影，为137维。七个条件logistic头、L2=.005、CPU float64 LBFGS80，校准集单独做正斜率Platt校准。模型仅由校准policy tokens/ms选择，选中 **F1**，之后才计算测试预测；没有依测试结果切换模型或训练MLP。

训练深度1..7的条件样本数为 **4740 / 3748 / 2773 / 2029 / 1532 / 1156 / 879**，成功数为3748 / 2773 / 2029 / 1532 / 1156 / 879 / 662。标签为“本轮能输出更多token”的累计进展事件，和原始匹配接受率并非同一量；EOS/cap会终止进展。条件拟合在上一进展事件成功的样本上执行。

输入remaining始终使用**配置输出容量减去已生成token数**，不使用距离未来EOS的长度。当前Target验证结果仅用于标签/校验，不能进入同轮预测输入。

F1在新测试的第五深度平均条件进展预测79.05%、实际226/284=79.58%；第七深度预测80.42%、实际143/179=79.89%。第一、二深度仍偏乐观，完整逐深度指标保留在数据中。任务和标签口径与E14不同，不把这些数字当成同任务误差降幅。

## 离线门槛

校准集选出的固定基线为 **8行（anchor+7草稿）**。仅用校准提示测量按短/长context汇总的verify+greedy commit曲线，以及native cached draft和F1特征路径的中位耗时。已付草稿费计入所有候选宽度，包含width1；已知剩余输出容量约束对所有组生效。

| F1离线均匀前缀replay | 估算收益 | 语义组bootstrap 95% | oracle-gap捕获 |
| --- | ---: | ---: | ---: |
| 校准 | +7.54% | +4.71%～+10.59% | 40.21% |
| 新测试 | +8.59% | +3.89%～+13.75% | 40.32% |
| SQL整族留出 | +4.67% | +3.84%～+5.57% | 27.44% |

测试948个位置中，667个选择了不同于固定基线的宽度，覆盖1..8行。与E14相比，重要的结构变化是预测确实可以改变动作，但两轮的TPS不能跨任务直接比较。

这里的oracle通过Dinkelbach迭代优化整套均匀前缀的SUM(tokens)/SUM(cost)；最大单步进展的lossless oracle单独保留。它们都不是实际在线吞吐上界。修复前“捕获240%”的反例现在得到正确吞吐oracle；另有整体比值、非单调成本、已知cap和分组重采样的回归测试。

门槛是新测试捕获≥30%、组bootstrap收益及捕获下限>0，校准/测试均有正收益与动作差异；本轮通过。SQL结果单列，未用于选择模型。测试仅6个语义组，区间描述这一小套件。

F0与F1的CPU预测中位耗时分别为0.0133ms和 **0.0528ms/轮**。校准估计的完整F1特征增量约为短context0.140ms、长context0.162ms；固定组和oracle不收预测器费，模型额外计入非负特征增量与CPU推理费。F0也保守计入F1特征增量。成本采用中位曲线近似，因此离线正结果不能代替在线计时。

F1的校准policy分数仅比F0高约0.04%，这里只按事先规定的点估计规则选定F1，**不能据此宣称hidden投影显著优于F0**。后续需要单独的在线特征消融。

## 在线结果

六条预先冻结的新任务，三组每组5轮，**90次正式计时、18次独立oracle、2286行committed logits全部通过**。90次正式计时均检查输出token及请求后live state。两条输入为1024/1536 token，均生成到128-token cap。所有组使用同一Target、Q4草稿头、cached草稿算术；固定组每轮生成完整草稿，原生组保留pre-draft和runtime反馈，预测器组包含全部特征/CPU传输/推理开销。prompt、state clone、oracle不计decode。

| 同任务完整decode | 加权tok/s | 各任务median耗时之和 |
| --- | ---: | ---: |
| 校准固定8行（anchor+7草稿） | 39.9555 | 19.0712s |

预测器相对固定基线吞吐 **+10.88%**、耗时下降9.82%；任务bootstrap耗时下降95%区间 **4.92%～14.10%**。相对lagged参考吞吐 **+10.00%**、耗时下降9.09%；区间 **5.45%～13.97%**。这些区间是本六任务的小套件描述，不能当作任意请求的保证。

### 收益来自预算的双向调整

每组均提交3810行。相对lagged参考，预测器验证轮数1358→1210，减少10.90%；验证行6105→5845，减少4.26%。它在高收益位置保留更长前缀，在低收益位置收缩，所以不是简单地“一律少验证”。相对固定七草稿，验证行9205→5845减少36.50%，轮数1185→1210略增2.11%，完整decode仍获得收益。

累计Target verification阶段从lagged参考77.7250s降至70.3384s；草稿/特征/预算阶段15.4589s→14.1937s，后者包含预测费用但因轮数减少而总量下降。这些是主机阶段计时，不能解释为纯GPU kernel效率或DRAM流量变化。

native参考与预测器组还存在post-draft决策、metadata和runtime反馈差异，在线收益属于**整条预测器预算路径**，不能全部归因于hidden投影或单一预测指标改善。尚未做F0/F1在线消融。

## 常驻、复现与边界

沿用既有resident worker和权重，没有下载或重新加载权重。结束后同PID319、同Target/DFlash对象、`load_count=1`、READY；原有失败计数1未增加。[复用证据](../results/e15/2026-10-21-resident-reuse.json)。每个模块/依赖实际源SHA和数据SHA随证据保留；实跑cache helper为`ee7a725`的原字节，与当前源码仅差EOF空行。训练显式在CPU执行并恢复线程设置，不更新Target/DFlash参数。

采集及校验实际耗时约16.14分钟；两种拟合、离线评估与bootstrap合计约2.03秒。主要成本在生成真实标签，而非训练小头。CPU测试111项：108通过、3跳过；另在Spark的PyTorch CPU环境执行七项confidence-head测试全部通过，包含实际拟合。

复现需已有固定准备环境。将`e15_collect.py`、`e15_tasks.py`、`e15_metrics.py`、`e15_train.py`、`e15_online.py`及新增package模块放入对应准备目录。按[worker协议](RESIDENT_RESEARCH_WORKER.md)分别提交确切源码SHA：先`e15_collect`的`{"smoke":true}`，再空参数正式采集；`e15_train`空参数，门槛通过才提交`e15_online`。不能为这些任务重载权重。

`python3 scripts/e15_export.py RAW_DIRECTORY results/e15`核对状态、源SHA并导出。原始合成轨迹/特征在gitignored目录，公开模型为实验JSON小头，不是Qwen/DFlash完整权重。不要混用不同draft算术、量化头、投影种子或feature codec；若这些改变，需要重采标签/重训。

这是当前TensorFold-derived Target、Q4 DFlash和原生MTPVarlen的同步单请求研究循环；不是完整DeepInfer异步引擎、随机采样、多请求batch、4K+或新的原生TensorFold排名。默认路径保持不变。下一步优先做F0/F1在线消融与更多真实任务、自然EOS完成和更长输出的复核，再考虑接入默认执行器。
