# E3：局部启停与两级验证策略实测

**两级策略在八个新提示上得到约 1.95% 的净 decode 速度提升；仅启停没有净收益。** 这是小幅改进，未兑现上一轮事后路径估算的全部空间。392 次计时的完整输出和最终有效状态与 serial 一致，所有八例自然 EOS。证据见[公开 JSON](../results/e3/2026-10-20-local-policy.json)，实现与边界见[固定方案](E3_LOCAL_POLICY_PLAN.md)。

## 数据与正确性

在测试前固定 16 个训练提示、6 个独立校准提示和 8 个新测试提示，文本不重复；未使用上一轮的事后最优路径训练。按真实 serial 前缀收集 854 个训练位置、154 个校准位置，逐行检查 target 验证 logits 和当前捕获特征。一个训练代码提示达到 256 输出上限，按截断保存；其标签反映已知剩余输出预算，不称为自然完成。其余训练提示及全部校准提示自然 EOS。

前置模型使用决策时已知的 target/anchor 投影、target top-2 差距和长度等标量；后置模型额外使用当前草稿九个分数。两个模型均为三个条件 logistic 头和独立正斜率校准，预测实际能输出超过 1/2/3 个 token 的累计概率，包含 EOS 的影响，不把 softmax 或 selector 分数直接当接受概率。

测试前冻结模型，SHA256 为 `81933ff0901ac6cef6a5c33cd9ea1d2c239055e53625dde6fb59130bdc8c4065`。八个任务完成后再次检查摘要；最后的测试 Brier 评估没有再拟合模型。源代码和运行参数摘要在 JSON 中。

每个测试的六个非 serial 模式先做一次独立正确性运行，共 48 次；已提交行 logits、完整 token 和最终有效状态逐 bit 一致。正式计时的 392 次运行只在计时外核对输出和状态。六项字面/格式属性检查通过；两个代码样本未执行，未据此给出通用质量评价。

## 策略实际做了什么

下表是七次重复合计的验证总行数，含 anchor。固定三个草稿始终为四行。

| 模式 | 1 行 | 2 行 | 3 行 | 4 行 | 草稿调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原动态 | 0 | 0 | 4 | 999 | 1003 |
| 仅启停 | 119 | 0 | 0 | 931 | 931 |
| 两级 | 119 | 70 | 105 | 749 | 924 |

两级使用了所有档位，草稿调用从 fixed3 的 1001 次降至 924 次，但总验证步数由 1001 增至 1043。少做草稿和多走小步相互抵消，不能仅凭调用下降宣布加速。前置/后置特征与决策总开销约 544.34 ms，平均每次决策约 0.522 ms，已计入净结果。

启停和选档是本项目的新 greedy 实验策略，复用了期望输出/成本的预算思想；不把它称为原始 DeepInfer 学习置信度头或完整调度器。原动态对照仍调用固定原生二进制，使用滞后经验率及相同环境的成本曲线。

## 预测质量与剩余限制

测试计时完成后，在八个新提示全部 394 个 serial 位置独立测 Brier，按位置加权：

| 预测 | 输出 >1 | 输出 >2 | 输出 >3 |
| --- | ---: | ---: | ---: |
| 前置 | 0.11364 | 0.16633 | 0.19784 |
| 后置 | 0.10337 | 0.12853 | 0.13323 |

后置在第二、三步的预测较好，但更好的平均预测不等于更低耗时。极短翻译的前置预测仍过于乐观，未能避免不必要草稿；说明请求中存在局部低接受，前置模型区分能力仍不足。只靠这 16 个提示和低维投影，不能期待复现已知未来的路径。

训练按位置等权，一个截断代码提示贡献 255/854 个位置，约占 29.9%；这使数据长度分布并不均衡。它是本轮覆盖限制，不能据此单独断言收益不足的原因，后续应在新的训练/校准/测试划分上检验。

成本模型来自校准 prompt 起始状态，新的两级策略尚未拟合上下文相关的成本曲面。原/带分数草稿的校准微计时使用固定先后顺序，不能将其微小耗时差解释为附加置信度反而加速；完整 decode 对照才是本轮性能证据。

原始 BF16 drafter 与官方分步算术的差异、target prefill 差异仍未解决。prompt 继续使用同一 decode 算术。本轮仅 greedy，当前草稿分数的使用不代表随机采样已证明正确；多请求和长上下文未覆盖。最长有效提交位置为 278，1536 仅为分配容量。

## 资源与交付

本轮 Torch allocated/reserved 峰值 72.6670/72.6855 GiB，结束前主机可用约 27.29 GiB，为结束样本而非全过程最小值。cgroup events 全零，其范围不包含全部 CUDA 统一内存。

原始捕获、投影训练行和日志保留在私有区，Qwen/draft 权重未改变、未发布。公开 JSON 包含本轮新拟合的小预测器系数和受控输出。复现入口为 `scripts/e3_local_policy.py --repetitions 7`，沿用外部环境、源和 checkpoint；按 JSON 中 `harness_sha256` 部署文件并保存 `local-policy-ready.json`。导出使用 `python3 -m scripts.e3_export_local_policy <private-json> <public-json>`。

后续把不变数学常量复用和 greedy EOS 验证截断作为独立工程对照；不将其收益归给学习预测器，也不将多个实验的比值直接相乘。

该[独立工程对照已完成](E3_DRAFT_FASTPATH_REPORT.md)：128 次计时中，缓存加 EOS 相对其同轮原始 fixed3 快约 1.26%，缓存单独未建立稳定净收益。没有运行学习策略与两项优化的组合。

另行核对固定 checkpoint 的 [config](https://huggingface.co/incoai/Qwen3.8-Flash-Next-DFlash2/blob/a22a1744e85c17364dcc54a6a420af7135d4c7f6/config.json)，`dflash_config.block_size` 为 8；[上游 README](https://huggingface.co/incoai/Qwen3.8-Flash-Next-DFlash2/blob/a22a1744e85c17364dcc54a6a420af7135d4c7f6/README.md)说明其 SGLang 评测只用 4 行，受当时 QSA 实现限制。我们的 target buffers/state 和 drafter 探针也仅验证至四行，不能把这个范围当成权重训练上限。更大的草稿/验证范围值得单独核对官方语义、GDN/QSA 状态和 SM121 算子后实测；当前没有八行兼容性或收益结果。
