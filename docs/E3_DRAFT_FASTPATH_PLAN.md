# E3 草稿常量复用与 EOS 验证截断方案

本轮作为局部预测器实验之外的独立工程对照。实现来自热路径检查：原草稿每次 rotary 调用都重建频率并计算 sin/cos，每次 norm 都重复将不变权重转换到 FP32。缓存内容仅由固定权重、位置和 dtype 决定，可以在初始化时复用。

`CachedDraft` 只缓存完整有界位置表（仍保留原 BF16 舍入边界）和 FP32 norm 权重；不缓存依赖当前上下文的 K/V，不更换草稿权重或 attention 算术。运行前比较包含位置 1535 的点运算，以及所有 norm 的有/无 residual 结果；正确性运行逐步比较真实完整 draft hidden 和 proposal 是否逐 bit 一致。

第二项优化是 greedy EOS 截断：若 proposal 第 j 个为 EOS，则它前面的输入已经能预测该 EOS。若它正确，生成在此结束；若错误，此处输出 correction 后本步结束。因此该 EOS 自身及其后续 token 都无需作为 verifier 输入。完整输出、有效提交位置和 processed-draft 契约在小词表上穷举验证，之后仍做完整 target 的 logits/输出/状态检查。此结论针对当前 greedy 契约，不外推随机采样。

四组为 serial、原始固定三个草稿、常量缓存后的固定三个草稿、缓存加 EOS 截断。每任务每组四次，按四阶循环 Latin square 轮换，共 128 次完整 decode 计时。另在相同 prompt 初始状态上进行原/缓存 drafter 六次 AB/BA 微计时，避免固定先后顺序。

使用局部策略实验的八个测试提示作为实现回归输入；在提出本优化时已观察过部分局部策略结果，不再称为新的未见测试。没有依据这些输入拟合新参数。比较同轮各组，不跨不同输入或不同运行时段直接拼接加速比。

开始本轮前等待局部策略实验完成并退出，不并发 GPU 压测。先验核对该实验的 token 输出；每个非 serial 模式先做 oracle 验证，正式计时只在计时外比较输出和最终有效状态。时间包含草稿、target 验证、状态提交和控制开销，排除加载、prompt、首个 pending token、状态初始化和正确性比对。四次重复不能单独支持显著性结论。

若缓存不能保持逐 bit hidden/proposal 一致，不将其作为无数值变化优化通过；若没有净收益则保留负结果。本轮不能替代 BF16 官方 fidelity、target prefill、多请求、长上下文、独立质量或服务性能验证。
