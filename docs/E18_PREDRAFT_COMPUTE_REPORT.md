## 实际执行与正确性

沿用同一个Target、DFlash与Q4输出头对象。12个E16 **train** 提示，英文/中文各6，覆盖解释、代码、长输入、数学、写作、实用指南。每条独立serial greedy到EOS或40-token cap，取0/8/16/24位置，共48前缀。它们是开发/训练探针，不是新held-out任务。

每前缀比较13个动作：不生成草稿且Target width1；真实4行backbone、3行head下的width1..4；真实8行backbone、7行head下的width1..8。三轮正式计时共**1,872次动作**，另624次预热检查；所有动作输出、已提交logits/live state对照通过，正式共核对4,449行committed logits。

Q4新增M=3存储权重算术检查通过；M=1/3/7相对误差约1.4e−7，最大绝对误差≤1.67e−6（小矩阵存储权重控制，不是完整BF16草稿fidelity）。全模式仍由同Target验证和提交，因此短草稿候选变化不应改变greedy输出。

4行是实际减少backbone与输出投影行数，**没有先算7草稿再截断**。但48前缀只有38个的三个草稿与七草稿前三个完全相同；同样验证4行时，进展总量132对134，46前缀相同、2前缀更少、没有更多的例子。不能把完整7草稿头的条件概率和特征契约无修改地套给3草稿。

## 计算时间并没有随行数减半

| 草稿阶段 | 真实block4 | block8 |
| --- | ---: | ---: |
| 已有cache、模拟追加8行，跨前缀中位耗时 | 9.7456ms | 9.7716ms |
| 冷cache跨前缀中位耗时 | 10.3598ms | 9.8373ms |

各前缀草稿耗时相加，block4比block8低**0.74%**。这是小套件三次计时的点估计，未证明稳定的小幅加速。草稿4先于8测量，缺少反向顺序的独立对照，冷启动4还更慢。不能从行数或浮点运算量推算同比例速度收益，也尚未通过阶段剖析确认具体瓶颈。

因此当前不应直接把默认七草稿改成三草稿。短草稿少了一些接受机会，而测得的计算节省很小。

## 可继续探索的是跳过整个草稿

以同前缀实测中位成本和真实进展做Dinkelbach聚合比值oracle，比较允许的动作集合；只用于决定是否继续研究，不是在线吞吐上界或实际速度：

| 可行动作集合 | 相对仅block8的理想前缀比值 |
| --- | ---: |
| block8，可选width1..8 | 参考 |
| 跳过草稿或block8 | **+3.06%** |
| 跳过草稿、block4或block8 | **+3.46%** |

在已有“跳过或完整草稿”的集合上，额外加入block4只增加约0.38%的理想比值。跳过/完整草稿的oracle在11/48位置选择跳过。其余位置继续利用完整七草稿。未计前置gate费用，样本均来自训练位置、最多40输出token、只模拟已有cache追加；不能把这些数当成下一轮在线收益承诺。

跳过草稿的Target仍捕获特征，供后续轮次恢复草稿使用；这不是完全不捕获特征的纯Target服务对照。前置gate只能使用本轮草稿生成前已知的信息，例如当前已提交上下文、既往轮次信号、已知剩余容量。当前七草稿的信号、当前Target验证结果或未来EOS都不可作为“提前跳过”的输入。

建议下一步先做低开销的**跳过/完整七草稿二选一gate**，保留block4为诊断动作；先以廉价、因果可用信号检查能否识别这些位置，再在新任务上完整在线验证。E17的七深度补训和这个gate分别评估，不把验证预算改善与草稿计算节省混成一个未经拆解的结论。
